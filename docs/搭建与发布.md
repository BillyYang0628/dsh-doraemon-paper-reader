# GitHub 打包、全新安装与独立迭代

## 1. 目标

仓库要同时满足三种人：

1. 只想在全新 DSH 中安装插件的普通用户；
2. 想读源码、跑测试、调试 UI 和宿主逻辑的开发者；
3. 只想改进 PDF 结构审计规则、又不希望碰插件 UI 的研究者。

因此发布物拆成两个：

```text
插件包
  dsh-doraemon-paper-reader-<version>.tgz
  → src / assets / cordis.patch.yml / Python 运行时入口

审计实验室包
  dsh-doraemon-paper-reader-audit-lab-<version>.tgz
  → audit-lab / pdf-pipeline / 审计实验文档 / 回归案例
```

两个包版本同步，但安装、运行和升级路径独立。审计实验室不包含 `src/`、角色
插画、DSH 页签或插件入口。

## 2. 新用户路径

新用户从 GitHub Release 下载插件 tgz，在 DSH 桌面端“插件 → 添加插件”中选择
该文件，安装后立即启用。命令行等价操作：

```powershell
dsh plugin --profile <profile> add D:\downloads\dsh-doraemon-paper-reader-<version>.tgz
```

安装包必须自包含：

- `package.json` 与 `cordis.patch.yml`；
- `src/` 全部宿主与浏览器半区；
- `assets/` 中的角色、精灵图和 KaTeX；
- PDF/HTML 管线与受管 Python 启动器；
- `README.md`、`INSTALL.md`、`LICENSE`、`THIRD_PARTY_NOTICES.md`。

安装包不得包含：

- `test/`、`工具/gen/`、`audit-lab/`、`.github/`、`dist/`；
- 论文 PDF、DSH 作业目录、截图、缓存、批注或 API key；
- Python `__pycache__` / `.pyc`。

## 3. 开发者路径

从 GitHub 克隆源码后，用户不需要先执行 `npm install`，因为插件没有 npm 运行时
依赖：

```powershell
npm run verify:offline
dsh plugin --profile dev add link:<repo>
npm run verify
```

项目级技能 `.dsh/skills/doraemon-dev-loop/SKILL.md`、`AGENTS.md`、
`CONTRIBUTING.md` 和 `docs/项目索引.md` 共同告诉新 DSH 会话如何继续开发。

## 4. 独立审计迭代

用户可直接运行：

```powershell
npm run audit:lab -- self-check
npm run audit:lab -- extract .\paper.pdf --out .\audit-lab\work\paper
npm run audit:lab -- audit .\audit-lab\work\paper --baseline .\old-audit.json
npm run audit:lab -- regression --keep-going
```

审计实验室的私有案例和产物目录已被 Git 忽略。用户可以：

1. 在 `audit-lab/cases/private/` 增加本地案例；
2. 修改规则；
3. 跑旧语料回归和 before/after 差分；
4. 只把稳定、通用、许可清楚的改动提交给插件仓库。

独立发布包把 `工具/pdf-pipeline/` 复制为包内 `pdf-pipeline/`，因此解压后不需要
插件 `src/` 也能运行。

## 5. 发布命令

正式发布要求 Git 工作树干净：

```powershell
npm run release:check
```

工作区仍有开发改动时，只能生成本地候选：

```powershell
npm run package:candidate
```

产物：

```text
dist/dsh-doraemon-paper-reader-<version>.tgz
dist/dsh-doraemon-paper-reader-audit-lab-<version>.tgz
dist/RELEASE_NOTES-<version>.md
dist/release-manifest.json
dist/SHA256SUMS.txt
```

`release-manifest.json` 记录 Git commit、是否存在未提交改动、包版本、DSH/Node
版本范围、文件数、字节数和 SHA-256。

## 6. GitHub 发布顺序

当前本机仓库尚未配置 `origin`，`gh` 登录 token 也已失效。维护者完成登录和 remote
配置后执行：

```powershell
git remote add origin https://github.com/<owner>/<repo>.git
git push -u origin HEAD
git tag -a v0.2.0 -F <release-notes-file>
git push origin v0.2.0
gh release create v0.2.0 `
  .\dist\dsh-doraemon-paper-reader-0.2.0.tgz `
  .\dist\dsh-doraemon-paper-reader-audit-lab-0.2.0.tgz `
  .\dist\RELEASE_NOTES-0.2.0.md `
  .\dist\release-manifest.json `
  .\dist\SHA256SUMS.txt `
  --title "v0.2.0" `
  --notes-file .\dist\RELEASE_NOTES-0.2.0.md `
  --verify-tag
```

不要在本机没有 remote 或没有明确授权时自动 push、创建 tag 或 GitHub Release。

## 7. GitHub Actions

`.github/workflows/verify.yml` 在 push、PR 和手动触发时：

1. 跑离线 Node/Python/文档/audit-lab 自检；
2. 检查 npm 包清单；
3. 在干净 checkout 上生成两个发布候选 tgz；
4. 上传 tgz、manifest 和 checksums 为 GitHub Actions artifact。

真实论文 PDF 不在公共 CI 中分发。`verify` 在本机有语料时运行七篇回归；
没有语料时不能把缺失样本写为通过。

## 8. 验收

发布候选至少满足：

- `npm run verify:offline` 全绿；
- 本机有样本时 `npm run verify` 全绿；
- 插件 tgz 可安装到独立 profile；
- 安装后 DSH 页签、宿主路由和静态资产可加载；
- audit-lab tgz 解压后 `npm test` 与 `node cli.mjs self-check` 可运行；
- manifest 的 SHA-256 与实际文件一致；
- 包内没有密钥、论文、截图、缓存或未声明的第三方运行时。
