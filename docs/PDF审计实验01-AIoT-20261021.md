# PDF 审计实验 01：AIoT 论文

## 1. 实验目标

本轮不以对话中已知的 bug 清单为输入，而是直接对同一篇 PDF 的原文行、版面资产、MirrorDoc 和最终报告做确定性差分，主动寻找未知问题，并完成一次“发现 → 归因 → 修改 → 复测 → 留证据”的闭环。

- SHA-256：`C83192CDA5FD891A43D698BF7B2679F791B8A86F79E457AF3A8C75F2B92FC5B9`
- 页数：19
- 许可：CC BY 4.0

过程产物都在 `工具/gen/audit-aiot-20261021/`，该目录可随时清理。

## 2. 审计方法

新增 `工具/pdf-pipeline/audit_structure.py`，只读以下产物，不改 MirrorDoc：

- `lines.json`
- `assets.json`
- `mirrordoc.json`
- `layout-report.json`
- `report.md` 的最终指标标记

每条 finding 固定带规则 ID、严重度、页码、blockId/sourceId 和证据。首轮支持：

- sourceId 重复、未知引用、内容行漏分配、furniture/meta 泄漏；
- 页顶 running header；
- 正文碎片误判标题、算法边界误判标题；
- Abstract 与元数据；
- 算法块、编号步骤和控制流缩进；
- paragraph 句中断裂与分位数；
- 行尾连字符还原、明确复合词连字符误删；
- 参考文献缺号/重号；
- 表格裁剪完整性、表格文字行边界；
- layout report 与最终 MirrorDoc 的指标是否陈旧。

所有指标从最终 MirrorDoc 重算。`report.md` 现在由 reconcile 写入 `final-mirrordoc` 标记，避免再把提取阶段的 603 blocks 当成最终结果。

## 4. 根因与算法迭代

### 4.1 页眉不能靠期刊白名单

旧逻辑只识别 `Sensors / Journal / IEEE / ACM` 等开头。改为：

- 页顶 `N of M` 显式信号；
- 数字归一化后的重复签名；
- 字号不高于正文；
- 不把唯一的页首编号标题当页眉。

### 4.2 独立 Abstract

`Abstract:` 和独占一行的 `Abstract` 都识别为结构标题；摘要正文仍按原行进入 abstract block，不再压成普通段落。作者行也从机构元数据中恢复。

### 4.3 run-in heading 误升格

旧实现会把“单行段落的字号”和“下一个 block 的第一行字号”比较，于是正文末行遇到下一个大标题时被误升格。现在：

- 只有一个 sourceId 的 block 永不自行拆出 run-in heading；
- 必须同时存在同一 block 内的标题行和后续正文；
- 句尾连接词、逗号、过渡句等不再进入目录。

### 4.4 Algorithm 结构

新增 `algorithm` block：

- 保留题注；
- 保留 12 个 numbered steps；
- 每步保留 `number / text / depth / sourceId / page`；
- BEGIN/END 不再进入目录；
- 控制流按 `WHILE / IF / ELSE IF / END IF / END WHILE` 计算层级；
- `algorithmText` 使用换行保存，阅读页与独立 HTML 都渲染为代码式步骤。

当前深度为：

```text
1  0  Initialize
2  0  WHILE TRUE DO
3  1  Read sensors
4  1  Upload
5  1  IF manual command THEN
6  2  Control according to manual command
7  1  ELSE IF thresholds THEN
8  2  Automatic controls
9  2  Automatic controls continued
10 1  END IF
11 1  Wait
12 0  END WHILE
```

### 4.5 长表裁剪

旧实现把题注后 260pt 内的横线全部当作表格，遇到长表就截断；遇到规则链中途断开又可能只拿到表头。

现在：

- 从题注后开始找连续横线链，不再有固定 260pt 上限；
- 在横线结束后，按同列连续短行扩展表体；
- 遇到真正 heading、句子型正文、表注或大间距立即停止；
- `tableText` 用换行保留源行边界；
- 审计器会检查裁剪边界之后是否还有连续 `%`/数字型表格行。

### 4.6 参考文献与连字符

- `5. [CrossRef]` 这类 citation-link tail 合并回上一条文献，不再新建条目；
- 行尾连字符不再一律删除。只有同一文档里存在完整拼接词时才拼回；
- 已存在完整复合词形时保留连字符，例如 `domain-specific` 不再变成 `domainspecific`；
- 真实软断词如 `con-` + `volutional` 仍会还原为 `convolutional`。

### 4.6.1 其他底层收口

- `BEGIN/END` 永不进入 heading；
- reconstruction dots 行归为 furniture，不再制造短段落；
- 第一页的 Funding/Copyright 清理规则不再误删后文 Funding 声明；
- `report.md` 由二次复核写入最终指标；
- 回归执行器在每个 PDF 后自动跑结构审计，结构问题会使回归直接失败。

## 7. 审计边界

本轮 after 的 `0 findings` 只表示确定性结构审计范围内通过，不代表 PDF 转义已经绝对正确。

仍未覆盖或未解决：

- 中文翻译语义准确性；
- 单元格级表格行列结构；
- R-013 内容横线/分隔符独立 block；
- 跨页表格的单元格语义；
- 脚注与正文的进一步语义分层；
- 对所有学科版式的泛化。

因此审计结果必须带着 `scopeLimits` 一起看，不能用“0 findings”替代中文逐段对照和更多论文样本。

## 8. 后续固定审计流程

每个新 PDF 按以下顺序跑：

1. 记录 PDF 哈希、页数与许可；
2. 在独立目录生成 before；
3. 跑 `audit_structure.py`，先保存基线，不边看边改；
4. 按 rule ID 归因，只改可复现的底层路径；
5. 重新 extract + reconcile 到 after；
6. 用 `--baseline` 比较 rule 增量；
7. 跑单测、旧三篇回归和用户样本回归；
8. 随机抽查算法、表格、公式、目录与参考文献；
9. 把未覆盖项写进 scope limits；
10. 通过后才把新样本加入固定回归语料。

常用命令：

```powershell
npm run audit:pdf -- <job-dir> --out <audit-dir>
npm run audit:pdf -- <after-dir> --out <audit-dir> --baseline <before-audit.json>
npm run test:pdf-regression -- --out 工具/gen/pdf-regression-audit-20261021-final3
```
