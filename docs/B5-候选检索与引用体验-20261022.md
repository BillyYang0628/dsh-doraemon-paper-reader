# B5：候选检索与引用体验

## 1. 完成范围

闭合 R-009 → R-008：

- 非标识符查询从单次 OpenAlex 搜索升级为多路召回；
- DOI / arXiv 精确路径保留，并有 DataCite 后备；
- 候选按同一批结果内的可解释匹配分排序；
- 首位明确标记为“最可能匹配 / 最可能原文引用”；
- 显示高/中/低置信度、匹配分和命中依据；
- 前两项接近时标记并列风险，不伪造唯一答案；
- 单路限流、超时或不可达时使用其余路线，并记录诊断；
- 引用蓝链继续使用业务化 invalid / metadata-only / none 降级，不暴露裸 400。

## 2. 多路召回

当前非标识符路径最多使用：

| 路线 | 作用 |
|---|---|
| OpenAlex 搜索 | 题录、作者、venue、摘要与 OA 信息 |
| Crossref bibliographic | 通用题录召回 |
| Crossref query.title | 标题字段定向召回 |
| DataCite | arXiv DOI、预印本、Zenodo 等 DataCite 来源的后备 |
| arXiv 标题搜索 | 预印本补充召回 |

查询变体：

- 完整字段；
- 完整标题；
- 去掉副标题；
- 标题 + 第一作者 + 年份；
- 标题 + venue + 年份；
- 作者 + venue + 年份。

每次查询最多选择 3 个变体。结果按 DOI → arXiv → 规范化标题去重，并保留每个候选来自哪些路线。

## 3. 排序与置信度

匹配分是同一批候选内的排序分，**不是概率**。评分信号包括：

- 标题 token / 字符相似；
- 作者姓氏重叠；
- 年份是否一致或相差一年；
- venue 相似；
- DOI / arXiv 是否与参考文献标识符一致；
- 摘要/题录与引用句、参考文献上下文的重叠；
- 是否来自当前论文参考文献表；
- 多路同时命中。

界面同时显示“匹配分 N/100 · 高/中/低置信”，以及最多三条排序依据。首位使用品牌色边框和文字标签，不只靠颜色表达。

## 4. 分层回归金标

种子文件：

```text

```

当前自动从本地 7 篇真实论文的参考文献抽取 60 条：

| 分层 | 数量 |
|---|---:|
| DOI 强标签 | 7 |
| arXiv 强标签 | 30 |
| 纯标题、需持续复核 | 23 |

查询类型覆盖 DOI 精确、arXiv 精确、标题、去副标题、标题+作者+年份、标题+venue+年份、作者+venue+年份。

必须在措辞上区分：

- 这是**回归金标集**；
- 不是全球学术检索准确率；
- 30～100 条只能证明当前分层样本上的质量；
- 新失败先进入失败样本，再决定是修算法、补路线还是人工修正标签。

本轮 OpenAlex 共享 IP 当日免费额度耗尽（HTTP 429），Crossref 与 DataCite 仍能返回结果。OpenAlex 进入冷却，避免请求风暴；这不计为“算法命中失败”，但按 `routeFailureRate` 单独披露。

## 6. 失败吸收流程

1. 运行 live 评估并写失败：

```powershell
npm run eval:citations -- --live `
  --failure-out test/fixtures/citation-failures-v1.json
```

2. 人工核对纯标题标签、错误候选和路线错误；
3. 将确认后的失败重新并入种子：

```powershell
npm run build:citation-corpus -- `
  --failures test/fixtures/citation-failures-v1.json `
  --out test/fixtures/citation-retrieval-v1.json
```

失败样本优先保留，不因总体均值下降而删除。

## 7. 可靠性边界

- OpenAlex 无 API key 时受共享 IP 日预算影响；429 后冷却 1 小时；
- arXiv API 在当前网络可能连接超时；连续失败后冷却 2 分钟；
- arXiv 精确查询优先 arXiv API，失败后自动走 DataCite；
- 搜索单次超时 8 秒，最多两个查询变体进入通用路线；
- 搜索结果缓存 5 分钟，最多 200 项；
- 每次最多向界面返回 12 个候选，内部保留总数供诊断；
- 纯标题参考文献的检索准确率仍明显低于 DOI/arXiv；
- 不应把匹配分展示成概率，也没有声称完成全学科校准。
