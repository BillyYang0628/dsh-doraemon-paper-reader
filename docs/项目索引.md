## 0. 目录结构

```text
根目录        AGENTS.md / README.md / CHANGELOG.md / LICENSE / THIRD_PARTY_NOTICES.md / package.json / cordis.patch.yml / icon.svg
docs/         设计文档与规范（本文件、功能框架、开发流程、决定台账、界面风格）
.dsh/skills/  项目级技能（rank 100，随仓库走；DSH 会话里按名加载）
src/          宿主半区（Cordis 插件）
  index.js      插件壳：apply(ctx) + 静态资源路由 /doraemon-paper-reader/assets/*
  identifiers.js 纯函数：输入 → 论文标识符（DOI / arXiv / PMID / 标题）
  assets.js     纯函数：资源路由判定（路径穿越栅栏 / 扩展名白名单 / ETag）
  client.js     浏览器半区（client half，单文件、无构建）：主界面 + 两条单篇入口 + 多篇综述选择页 + 阅读页 + 全宽对照 overlay
assets/       随包发布的界面资产（透明角色、精灵图与小物件；源图不进仓库）
test/         L0 单元测试（node --test）
UI/           用户给的主形象挑图与后续界面素材（当前只有两张来图，见 §5）
工具/gen/      过程记录：截图、走查产物、抓取结果（可随时清，不入库）
工具/e2e/      浏览器自动化（L2）：驱动真实 dev 实例做断言与截图
工具/dev/      长期有效的开发辅助（overlay 等）
工具/          长期开发脚本（check-doc-links、preview-image、palette、export-asset）
```

> 命名规则：`工具/gen/<主题>-<YYYYMMDD>/` 放过程产物；长期文档用主题名，**不带日期、不带版本号、不用"最终版/最新/副本"这类词**。

## 6. 什么时候动这份文件

| 事件 | 必须做的动作 |
|---|---|
| 新写一份文档 / 新加一个源文件 | 在对应分类加一行（含 ✅ 与日期） |
| 结论变了 | 旧文档标 ⛔ 并写取代者；新文档标 ✅；**两行都更新** |
| 一轮核查 / 走查结束 | 产物放 `工具/gen/<主题>-<日期>/`；产生长期结论就抽成正式文档，过程留在原地 |
| 引用外部原文（文档、API 说明） | 原文摘录留在 `工具/gen/`，正式文档只写结论 + 出处链接 |
| 发现两份文档说法冲突 | 以 `docs/决定台账.md` 为准；其余按"更近 + 有实测证据"取舍，**别让两份都活着** |
| 每次提交前 | 花 5 秒确认这份索引与实际文件一致 |

## 7. 简化原则（简化 ≠ 删结论）

**可以简化**：重复的推导（只留一处，别处指路）、已被代码取代的伪代码、同一次试错里的重复调试输出与流水账。

**不能删**：数据不变量与业务口径、验收标准与回归入口（脚本名 + 期望结果）、踩坑结论与"为什么否掉某方案"、
外部依赖原文摘录与出处、以及**实测证据的线索**（脚本名、日志路径、截图路径、日期、哈希）。

判断口径：**将来遇到相似问题时，看这段能不能少走一段弯路**——能就留。
