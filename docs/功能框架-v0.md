## 0. 项目一句话

在一个**本地优先**的 DSH（DeepSeek Harness）工作台里，把"读论文"做成可交互的闭环：
**中英对照阅读 → 划词查义 → 就地追问 → 勾画批注 → 沉淀生词与笔记**，
而不是每次让模型把整篇重排成一份译文再从头读。

与"直接生成整篇中文版"的关系：两者互补——动态阅读要的是"边读边想"，整篇重排要的是"可归档的成品"。

## 1. 目标能力（需求侧拆解）

### 1.1 阅读
- 在工作台里直接打开本地 PDF 论文（不跳出到外部阅读器）
- **（R1 修订）入口不止本地 PDF**：DOI / arXiv ID / 标题+作者 / 刊+卷+页 / 粘贴链接 / 上传 PDF 反查
  —— 先统一成"论文标识符"，再进获取与镜像流水线，详见 §12-R1
- **中英对照**：两种形态——分屏（左原文 / 右译文，滚动同步）/ 单页内对照
- **原文 ↔ 纯中文** 原地一键切换，每篇记住上次用的视图
- **公式保护**：公式不被翻坏；理想状态下可点、可搜（点公式把 LaTeX 带进提问）
- 扫描件 / 无文本层 PDF 也能读（OCR 兜底）

### 1.2 词汇
- **划词查询**（词或短语）→ 浮层给出：词性、音标、义项、**在本句中的含义**
- 与"整段翻译"分流：词级走词典源（可离线、零 token），段级走模型翻译
- **生词入库**：一键收藏、列表查看、按时间/掌握度复习、能发音

### 1.3 批注与勾画
- 在 PDF 正文上高亮 / 下划线 / 圈注，并写批注文字
- **持久化**：关掉再打开还在；可跳转、可汇总、可导出 Markdown
- 批注能作为上下文带进与模型的问答（"第 3 处批注我不认同，为什么？"）

### 1.4 伴读（做题式学习）
- 选文即问；**回答带页码**，点页码平滑跳回原文并高亮
- 追问、按论文组织的历史会话
- **学习档案**：分步阅读计划、检验题与成绩、进度累积

### 1.5 文献管理
- 专题 → 论文 两级库；上传 / 重命名 / 删除（回收站可恢复）
- 原文、译文、解析产物、批注、生词**跟随论文一起搬迁**
- 检索：关键词 + 语义（可选，需要 embeddings 端点）

### 1.6 论文获取与镜像（R1 新增）
- **多形态输入 → 统一标识符**：正则识别 DOI `10.xxxx/…`、arXiv `xxxx.xxxxx`、PMID，其余走标题匹配；
  内部主键优先级：DOI → arXiv ID → PMID/PMCID → 标题+年份哈希
- **渠道阶梯优先级**：按刊物编排（venue 档案表），并**回写本地成功率台账**动态调整顺序
- **合法镜像源**：arXiv/ar5iv 官方 HTML、PMC/DOAJ/机构仓储/作者自存、用户本地 PDF；
  **付费墙只做深度链接 + 元数据 + 摘要 + 引用图谱，不抓正文**
- **镜像页面固定形式**：统一中间表示 `MirrorDoc`（章节树 / 块级元素 / 图表占位 / 引用锚点 / 版本戳），
  由 HTML 摄取器与 PDF 摄取器分别产出——阅读器只认 `MirrorDoc`，不认来源
- **引用蓝链**：正文 `[n]` → 对应参考文献 → DOI → 可点击；hover 可给题目/作者/被引数/是否 OA
- **版本显式化**：VOR / 录用稿 / 预印本 / OCR 重建 / 译文，来源 + 许可 + 抓取时间 + SHA256；
  **每次提问自动注入版本信息**；"强制正式版"走官方下载 + 一键确认后重建镜像
- **异步深处理**：整篇翻译、版面解析、摘要生成走后台任务与进度可见（首版不设 10 秒门槛，但保留省时设计）

## 4. 关键架构事实（决定方案形态，别跳过）

### 4.1 DSH 提供的"插座"【已核】
1. **插件形态**：一个 npm 包可以同时有
   - 宿主半区（Node/Cordis 插件：注册工具、HTTP 路由、调 `ctx.llm`）
   - 浏览器半区（`dsh.client`：React 组件、DOM、浮层）
   - 通过 `cordis.patch.yml` 作为 bundle 层插入 profile
2. **UI 扩展点**：
   - `slots` 类型化插槽系统（`single` / `list` / `keyed` / `chain`）
   - `sidebarRightTabs`：注册新的**页签类型**（可接管内置查看器）
   - `documentPreviews`：按扩展名注册**文档渲染器**（可对 `.pdf` 顶掉内置查看器）
   - `shell.overlay`：整帧浮层（做词汇卡、批注面板的天然位置）
   - 会话节点、输入框周边若干插槽
3. **服务侧**：`ctx.tools`（模型工具）、`ctx.webServer`（自有路由）、`ctx.llm`、settings、locale、`dsh-resource://` 资源模型
4. **隔离**：每个 profile 独立装插件、独立启用；跨插件不能互相 import 运行时值

### 4.2 paper-reader 的真实形态【已核】
```
宿主半区          src/index.ts → inject['tools'] → 5 个工具
                 list_papers / transcribe_pdf / search_paper / study_progress / study_update
                 src/host.ts  → /paper-reader/* 路由（鉴权 + sessionController + follow SSE）
                 纯函数模块：transcribe(取文) / mineru(解析) / formulas(公式索引) /
                            translate + translate-selection(翻译) / search + embed(检索) /
                            library + library-manage(库管理) / study(学习档案) / babeldoc-install
浏览器半区       lib/client.js：接管 sidebar.workspaces 做文献库树 + 注册 PDF 页签
阅读器           reader/index.html：**独立 iframe 页面**，自带 pdf.js + KaTeX
每篇论文产物      <名>.pdf/.txt/.pages.json/.transcript.json/.mineru.md/.mineru.json/
                 .embeddings.json/.study.json，译文变体 -zh.pdf / -dual.pdf / -en.pdf
```

### 4.3 三条结论（这是方案的根）
1. **"三合一"不能靠拼插件**：`dsh-annotation`、`dsh-selection-explain` 都靠注入 DSH 主 DOM 工作，
   而阅读器是**独立 URL 的 iframe**；社区插件自己也声明"独立 URL 加载、无法注入划词桥的页面不触发"。
   → 想一体化，只能在**阅读器内部**实现（即扩展基座），或者自己重写阅读器（重复劳动）。
2. **paper-reader 已覆盖约 2/3**：阅读、中英对照、划词翻译（含公式还原）、带页码问答、学习档案、文献管理都有；
   **缺的是词级词典与持久批注**。
3. **它对 AI 协作友好**：仓库里有 `AGENTS.md`（明写"给 AI 协作者的项目说明"）、三平台 CI、
   以及"改产物后缀必须同步改两处 README"这类测试守卫——动手术的成本可控。

## 5. 路线选择

| 路线 | 做法 | 代价 | 结论 |
|---|---|---|---|
| **A. 基座扩展**（推荐） | 以 paper-reader 为基座，在它内部加"词典查询 + 批注勾画" | 需要 fork，跟随上游更新要做合并 | 复用最难的部分（pdf.js 阅读器、翻译流水线、MinerU、锚定） |
| B. 自研外壳插件 | 新写一个插件，自己实现 PDF 阅读 + 翻译 + 解析 | 数周级、重复造轮子 | 不推荐 |
| C. 纯插件拼装 | 装 paper-reader + 划词插件 + 批注插件 | 划词/批注进不去阅读器 iframe | 体验割裂，只能算过渡 |
| **D. 上游贡献** | 把 A 的增量做成 PR 提给作者 | 受评审节奏约束，功能可能被拆小 | 最优长期解，但需先探作者意愿（其 TODO 里暂无批注/词典计划） |

> **R1 修订**：结合"零源码依赖"要求，路线倾向调整为 **自研整合包（借鉴 + 多处重写）**：
> 不把任何社区插件列为依赖、不 import 其运行时、不 monkey-patch 官方服务；
> 参照 §12-R1 的"借鉴矩阵"逐项重写。A/D 仍可作为局部策略（例如只为拿到某个思路去读上游源码）。

各层职责：
- **数据层**：纯文件、可读可 diff、可手工修；新增两种产物后缀需同时改两处 README（该仓库的测试守卫）
- **服务层**：宿主侧纯函数 + 路由；词典与锚点服务新增，互不耦合
- **阅读器前端**：pdf.js 文本层提供选区与坐标；高亮用绝对定位图层（现成先例：公式 bbox 热区）
- **会话桥**：沿用现有 `sessionController` + SSE，把"选文/批注/生词"带进对话
- **插件外围**：侧栏树、页签、设置卡片、i18n（zh 字典已具备）

## 10. 风险与约束【风险】

1. **上游处于开发者预览**：官方明说会有破坏性变更；插件靠 peer 版本校验，升级后可能被拒载或需重装（社区实测：升级后启用开关会重置、不带版本号的 `add` 是 no-op）。
2. **iframe 隔离是生态整合的天花板**：任何"在阅读器上加功能"的第三方插件都做不到，只能进基座。
3. **重依赖**：中文版 PDF 依赖 babeldoc（Python，插件会自动装 uv 托管解释器），扫描件/公式依赖 MinerU（本地或云端）。Windows 上的安装成功率需要实测。
4. **成本**：按页/按段翻译走模型 token；词典走离线可归零。
5. **数据位置**：这类插件的默认数据目录常在 C 盘用户目录下，必须显式改到 D 盘（当前 C 盘可用 17.2 GB）。
6. **许可证**：可复用资产基本是 MIT；`dsh-scholar` 无许可证（排除），`@huanlin/dsh-plugin-better-locale` 是 AGPL（对我们无用）。

## 附录 B：名词速查
- **DSH / DeepSeek Harness**：DeepSeek 开源的 agent harness，"一切皆插件"（底层 Cordis）

- **babeldoc**：把 PDF 翻成中文版/中英对照版的引擎
- **embeddings 端点**：任意 OpenAI 兼容的向量接口，用于语义检索
