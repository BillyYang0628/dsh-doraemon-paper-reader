### 2.4 用法比例

参照主形象自身的配色占比来分配界面：**主蓝系 ≈ 15%、白/米白 ≈ 25%（大面）、深蓝系 ≈ 15%、其余留白**。
霓虹感、渐变光晕、彩色玻璃这些都不属于这套色板。

## 3. 像素风规范

界面沿用主形象的像素风，但要**"像素作为质感，不是作为限制"**——可读性优先于像素纯粹主义。

| 项 | 规范 |
|---|---|
| 像素网格 | 一切像素元素按**整数倍**缩放（1×/2×/3×，或 CSS 里的 `image-rendering: pixelated` + 整数尺寸）；非整数缩放会糊掉像素颗粒，直接判不合格 |
| 描边 | 图标与插画用 **1 逻辑像素**墨蓝黑（`#10101A`）实心描边；不要用 box-shadow 模拟模糊描边 |
| 阴影 | 硬边偏移阴影（`2px 2px 0`/`4px 4px 0`）而不是模糊阴影；只有浮层允许一层克制的模糊投影以表达"浮起来" |
| 明暗 | 一个形状最多 3 档色阶；过渡用**硬边色阶或棋盘格抖动（dithering）**，不用平滑渐变 |
| 圆角 | 见 §4 —— 像素风与圆角并存的方式是"**阶梯状圆角**"，不是抗锯齿圆弧 |
| 图标 | 16/20/24 逻辑像素三档；同一套图标必须同一网格、同一描边宽度、同一光源方向（左上） |
| 禁止 | 抗锯齿斜线、平滑渐变底、玻璃拟态、霓虹发光、写实材质贴图、emoji 当图标 |

> 已有先例：仓库根 `icon.svg` 就是自绘的抽象"机器猫 + 文档"，本指南的色彩与描边规则同样适用于它（后续换正式图标时按 §5 档 B 出图）。

## 4. 圆角规范

| 圆角半径 | 用在哪 |
|---|---|
| `2px` | 标签、徽章、像素图标底衬 |
| `4px` | 小按钮、输入框、下拉项、代码块 |
| `6px` | 卡片、列表项、工具栏容器 |
| `8px` | 面板、页签容器、浮层卡片 |
| `12px` | 大容器、空态插画框、模态窗 |
| `999px` | 胶囊按钮、头像、状态点 |

实现规则：

1. **偶数半径**（2/4/6/8/12），保证在 1× 与 2× DPR 下都落在整像素上；
2. 圆角与描边同时存在时，**描边跟随圆角走**（`border-radius` 与 `border` 一起给），不要"方形描边套圆角底"；
3. 像素风插画（档 P）用**阶梯状圆角**：由 2px 的方块逐级内缩画出弧线，不做抗锯齿；界面容器则用正常的 CSS 圆角——两者在观感上通过统一的 4px 网格对齐，不强行一致；
4. 同一层级内圆角**只用一个值**，不要"卡片 6px + 里面按钮 8px"这种倒置。

> **落地口径（2026-10-16 增补，决定 D-022）**：真实插件里的容器与控件**优先吃宿主圆角 token**
> `--dsw-radius-xs|sm|md|lg|xl|panel`（实测 4 / 8 / 12 / 16 / 20 / 28px），因为这同时满足"圆角容器"
> 与"只用宿主 token"两条要求（`AGENTS.md` §2.6）。上面那张固定 px 阶梯只在没有对应 token 时兜底。
> **字号同理**：正文跟随 `--dsh-content-font-size` / `--dsh-content-font-size-secondary`，别写死。

## 5. 吉祥物插画系统

### 5.1 什么时候让吉祥物出场

只在**"有人味的时刻"**出现：空态、错误态、加载/等待、成功反馈、首次引导、长任务的进度陪伴。
**不出现的地方**：正文阅读区、批注浮层、表格与图表内部、任何会盖住内容的常驻位置。

出场时**一屏一个**，不重复堆叠；同一屏不要同时出现两种画风档位。

### 5.3 表情清单

`微笑`（默认）、`眯眼笑`、`专注`（读书时）、`惊讶`、`困惑`、`得意`、`委屈`（快哭了）、`哭`（流泪）、`困倦`、`鼓起脸`（轻生气）。
表情只改眉眼嘴，**不改**发色、瞳色、兜帽与披风的结构。

### 5.4 画风档位

| 档 | 名字 | 特征 | 用在哪 |
|---|---|---|---|
| **P** | 像素档 | 与主形象同款 16-bit 像素卡通；1px 描边、有限调色板、硬边色阶 | 界面内空态/状态插画、加载逐帧、徽章 |
| **C** | 卡通档 | 更软萌的**圆脸 + 大眼 + 腮红 + 简洁线条**的卡通感；线条圆润、色块平涂、可轻微渐变 | 大插画、引导页、README 与文档配图 |
| **L** | 线稿档 | 单色描边线稿（墨蓝黑），无填充或只填 1 档浅色 | 骨架占位、加载骨架、图标化插画 |
| **B** | 徽章档 | 圆形/圆角方形头肩像，背景为米白或主蓝实底 | 插件图标、页签、头像、收藏夹封面 |

各档**共用同一套身份特征与色板**（§2），换的是笔触与细节密度，不是角色性格。

### 5.5 文件与命名规范

- 命名：`mascot-<姿态 id>-<表情>-<档位>.png`，例如 `mascot-error-cry-cry-P.png`；
- 格式：界面用小图优先 **透明背景 PNG**（需要米白底时用 CSS 铺 `#EDE0C6`，不要烘进图里）；
- 尺寸：源图统一 **2048×2048** 或 2048×1536，界面按 **@2x 整数倍**引用（480 逻辑像素 → 960 实拍）；
- 落盘：**已定（D-026）**——界面用的小图进 `assets/mascot/`，由 `工具/export-asset.py` 从源图导出；
  源图（2048×2048）与临时出图落 `工具/gen/mascot-<YYYYMMDD>/` 或 `UI/`，按 `AGENTS.md` §2.5 可清可再生成、**不进仓库**；
- 看图和贴图前必须先跑 `python 工具/preview-image.py <文件或目录>`（`AGENTS.md` §2.7 / 决定 D-016：全尺寸图会撑爆 48 MiB 请求体）。

### 5.7 两类红线

1. **角色身份红线**：发色渐变、瞳色、兜帽白面板结构、披风双层下摆、鲸鳍耳、呆毛、鲸尾 —— 任何一张插画都不许改其中任何一项；改了就不是同一个角色。
2. **IP 红线**：卡通档要的是"软萌可爱"的**观感**（圆脸、大眼睛、腮红、简洁线条、暖色），
   **不要**在提示词里点名任何品牌或角色，也不要复制其专属造型元素（贴纸发饰、商标字样）。
   实测依据：指名知名 IP 的请求会被 DashScope 输出审核驳回（`IPInfringementSuspect`，见 D-017）；
   仓库既有的 `icon.svg` 也是按"自绘抽象"处理的。

## 6. 间距与字号（建议值，未在真实界面跑过）

- 间距走 **4px 网格**：4 / 8 / 12 / 16 / 24 / 32；
- 容器内边距：卡片 12–16、面板 16–24、浮层 16；
- 字号：正文 14、次级 12、标题 16–20、大标题 24；行高 1.5–1.6；
- 像素风小标题可以用像素字体，但**正文不用像素字体**（可读性优先，且中文字形集太大）。

| 主色 / 链接 | `#428AC7`（非文字） | `#7CACC4` |

| 警告 | `#6B4A00` | `#D9A93C` |
| 成功 | `#2A6B45` | `#4EA36E` |

暗色侧对比度已实算：`#F6F6EE` on `#1B1F36` = 14.92:1（AAA）、`#C3CBE0` = 9.98:1（AAA）、
`#7CACC4` = 6.60:1（AA）、`#D9A93C` = 7.48:1（AAA）、`#E58A7A` = 6.36:1（AA）、`#4EA36E` = 5.24:1（AA）。

**明暗两套都要正常**：插画本身是米白底画出来的，放到暗色主题里要么用透明背景 PNG、要么加一圈深蓝描边托底，
**不要**让米白方块直接压在暗底上。

## 8. 无障碍与动效

- 正文文字 ≥ 4.5:1，大字/图标 ≥ 3:1（§2.3 已给可用组合）；
- 颜色之外必须有第二重线索（错误用图标 + 文案，不只用红色），照顾色觉差异；
- 焦点态用 2px 主蓝描边 + 2px 偏移，不靠颜色变化单独表达；
- 加载动画（含像素逐帧）遵循 `prefers-reduced-motion`：降级为静态图或纯文字；
- 像素插画要提供 `alt` 文本，描述姿态与用途（"正在哭泣的吉祥物，表示加载失败"）。

## 10. 主界面（v0）与文案语气

> 落地实现：`src/client.js`（唯一实现）。结构由决定 D-020 定，视觉口径由 D-022 定，语气由 D-021 定。

### 10.1 结构：非对称阅读桌 + 两条并排入口

```text
┌ 右侧栏页签「论文阅读器」（kind: doraemon-paper）────────────────────┐
│                                                                   │
│  00 / PAPER READER                         ┌──────────────┐       │
│  陛下要小的我如何取来论文                  │ 大肥鱼贴纸   │       │
│  小的我更推荐 PDF 途径哦，陛下~            │ 欢迎回来     │       │
│  [PDF 文件] [DOI] [arXiv]                  └──────────────┘       │
│                                                                   │
│        ┌────────────────────┐  ┌────────────────────┐             │
│        │ [一页纸图标]   01  │  │ [放大镜图标]   02  │             │
│        │ PDF 文件           │  │ 信息查询            │             │
│        │ 把下载好的论文…    │  │ 只给我 DOI 或…       │             │
│        │ 进去看看 →         │  │ 进去看看 →         │             │
│        └────────────────────┘  └────────────────────┘             │
│                                                                   │
│        ┌ 多篇综述 ─────────────────────────────── 开始对照 → ┐   │
│        └──────────────────────────────────────────────────────┘   │
│        最近论文 · N 篇                              刷新           │
│        标题 / 作者 / 标识符 / 批注数                              │
└───────────────────────────────────────────────────────────────────┘
```

规则：

1. **落点**是右侧栏页签类型（`sidebar.right.pane.tab` 席位），不是自建页面、不是 iframe（`AGENTS.md` §2.6）；
2. 两条入口是 **`<button>`**：键盘可达、`:focus-visible` 有 2px 主色描边 + 2px 偏移；
   点击各开一个路径页（`doraemon-paper-file` / `doraemon-paper-lookup`）；
3. Hero 采用**非对称两栏**：左侧眉标/问题/说明/能力标签，右侧一张贴纸式主形象；不再使用“插画在上、内容居中”的旧结构（D-070）；
4. 两条单篇入口继续并排，`01/02` 只作视觉序号，不替代按钮语义；第三条「多篇综述」保持独立通栏卡；
5. 最近论文是可点列表，展示标题与两层元信息，不抢主入口视觉层级；
6. 窄格收内边距并把贴纸缩小，**不改并排入口结构**；375px 实测无横向溢出；
7. PDF 入口、加载页、阅读页沿用同一阅读桌语言：路径页有顶栏/步骤条，阅读页有目录轨与独立正文卡；
8. 用色只走宿主 token，字面色值只出现在插画上（D-022）；展示性 DOM 可以调整，但现有功能处理器、状态、API 与持久化不得改坏。

### 10.3 插画现状：用定稿主形象，别再自绘

**结论（2026-10-16，D-026）：界面插画 = 定稿主形象本身。** 我先前自绘的 32×32 像素吉祥物稿已**退役**——
真机上它被用户判为"太垃圾、和页面色调完全不搭"，判断是对的：饱和蓝 + 硬黑描边是另一套观感，
而主形象是柔和的深海蓝。**自己画的替代品永远不如已经把形象定下来的那张图。**

- 资产：`assets/mascot/mascot-hello-smile-c.webp`（512×512，72 KB），由 `工具/export-asset.py`
  从 `UI/mascot-v1.png`（2048×2048 定稿）导出——**源图不进仓库，进仓库的是能再生成的小图**；
- 送达：宿主半区的静态路由 `/doraemon-paper-reader/assets/*`（`src/index.js` + `src/assets.js`），
  前端用**相对地址**引用（不带前导斜杠），代理挂子路径时也解析得对；
- 形态：主形象自带**米白画布**，所以界面里就按"米白圆角卡片"展示（`--dsw-radius-lg` + 1px `--dsw-alias-border-l2`），
  这符合 §7 的"米白底插画要托底"；暗色主题下它是一张明信片式的亮卡（已实测）。
  想要"浮在背景上"的版本可以用 `export-asset.py --cutout` 抠底，但**实测抠图会留下地面阴影与封闭区残色**，
  当前不用（想要就得先修残色）；
- 出口尺寸：主界面 168px、路径页 120px，都低于 512 的源尺寸（高 DPR 下仍清晰）；
- 仅存的像素画法是**两枚 16×16 入口图标**（一页纸 / 放大镜，2× → 32px），颜色仍取 §2.1 实测值，
  L0 断言"坐标在网格内、颜色来自色板"。

> 教训（配合 D-025）：**像素稿不能只看 ASCII 定稿**；现在这条升级成更硬的一条——
> **形象类插画不自绘**，直接用定稿图（或按 §5.6 的参考图锚定路线出图）。
> 审图用 `工具/e2e/main-interface.mjs --mode art`（真机里把插画放大到 2× 截图）。

### 10.4 阅读页“原版 P.n”层级

- 连续正文、标题和参考文献按页合并页标：同一页只在文流中显示一次；
- 段落继续按 MirrorDoc 分段显示，不因页标合并而合并正文；
- 算法、代码、图、表、公式、未匹配 caption 属于特殊信息，必须保留自己的页码入口；
- 普通文流页标用 `is-flow`，透明度和字重较低；特殊块用 `is-special`，视觉上更容易定位；
- 页标仍是可点击按钮，打开插件内原页查看器，不退回死链或新窗口；
- L2 必须断言：flow 页标数少于段落数、flow 页标同页不重复、特殊块存在独立页标。
