# P1 多文本对照设计

## 1. 为什么不能只做一个“对比”按钮

P1 里看起来都像“同时看两篇论文”，实际是三种不同任务：

| 模式 | 关系 | 核心问题 | 证据规则 | 典型入口 |
|---|---|---|---|---|
| 综述对照 `survey` | A、B 是独立论文 | 两篇的问题、方法、结果、局限有什么异同 | 每个对照格必须有论文 blockId；无法定位就写「未找到」 | 主界面「多篇综述」 |
| 引用对照 `citation` | A 引用 B | A 在 `[n]` 处的说法是否真的被 B 支撑 | 关于 B 的结论只能引用 B；A 只用于确定主张与引用位置 | 正文引用蓝链 / 阅读页「双篇对照」 |
| 版本对照 `version` | A、B 是同一篇论文的不同副本 | VOR 与预印本之间哪些段落新增、删除或改写 | 用确定性段落比对，不把“文本不同”直接等同“语义冲突” | 阅读页「版本对照」 |

三者不能共用一套“谁更支持谁”的提示词：综述需要横向归纳，引用需要主张—证据链，版本需要保持两边文本身份。后端协议和前端文案都按这三种任务分开。

## 2. 总布局

工作台是全宽 `shell.overlay`，不塞进 343px 右侧栏：

- **左侧 8**：两篇 `PaperPane`，上下占满、左右并排；每篇继续复用单篇能力——正文、引用蓝链、选区批注、逐字高亮、原文/中文/对照、术语表、KaTeX、表格网格、版本徽标。
- **右侧 3**：`CompareWorkspace`。负责对话、批注列表、命令和产物入口；支持两篇论文同时进入上下文。
- **最右窄轨**：产物按钮隐藏时只占约 30px；点开后是小列表，再点具体项打开可拖动、可缩放、可多开的浮窗。

这样左侧保持“研究材料”的连续阅读，右侧保持“分析动作”和“可带走产物”，不会用一张固定表格挤掉全文。

## 3. 上下文与检索

单篇全文可能在几十 KB 到数百 KB，Responses API 又是无状态请求。对照层因此使用 `src/digest.js`：

- 每篇压成标题、作者、年份、标识符、版本、摘要、章节、关键段、图表公式参考文献计数；
- 默认单篇 ≤4800 字符；
- 章节和关键段都保留 `blockId/page/section`；
- 引用对照额外读回引用处原文与前后文；
- 用户当前批注按论文分组，随问题一起发送；
- 需要更细原文时，回答给 `dsh-resource://doraemon-paper/<jobId>/<blockId>` 或对照栏锚点，不把全文无限重传。

## 4. 产物分型与真实性边界

| 产物 | 数据来源 | 允许模型自由发挥吗 | 失败策略 |
|---|---|---|---|
| 七字段对照表 | 模型归纳 + 每格 blockId | 文字可以归纳，锚点必须可核 | 无锚点标「未定位」，无内容标「未找到」 |
| 论证链 | 七字段表的问题/方法/结果/局限 | 只重排已有字段 | 缺字段显示「未找到」 |
| 结构统计 | MirrorDoc 的图/表/公式/参考文献计数 | 不允许 | 计数始终来自确定性统计 |
| 证据覆盖 | 七字段表 grounded/missing/ungrounded | 不允许 | 0 值不画假条 |
| 有出处数据图 | 模型选已有数字 | 只能选择，不能换算/编造 | 每个点校验 `jobId/blockId/quote`，失败即丢弃 |
| 概念图 | 模型组织问题、方法、证据、结果、局限、缺口、机会 | 允许组织关系，但事实节点必须带锚点 | 无效锚点降级为“模型归纳”；无出处数字节点丢弃；无效边忽略 |
| 汇总/报告 | 当前档案、表、批注、对话、引用结论 | 只做摘要 | 模型失败时仍可导出已有结构化内容 |

这里刻意不做“自由位图生成”：图像很难自动核验，容易让用户把模型想象当成论文证据。概念图用 SVG/HTML 表达可检查的关系；数据图只画可回原文的数字。

## 5. 工作台交互

命令同时支持按钮和自然语言：

- “生成对照表” → 七字段表；
- “论证链 / 逻辑图” → 从表格抽问题→方法→结果/局限；
- “概念图 / 关系图 / 流程图” → 调概念图规划器；
- “数据图 / 趋势图 / 柱状图 / 折线图” → 调有出处数据图；
- “结构统计” → 文献元素计数；
- “证据覆盖” → 七字段定位率；
- “汇总 / 导出报告 / 归档” → 文字汇总、Markdown 下载、本地归档。

批注不必先切换模式：在任一 `PaperPane` 选中文字，写入问题后进入右侧批注列表；下一条工作台问题会把两篇论文的待发批注一起带上，并在发送后标记 `sent`。

## 6. 版本对照

- 论文库按 DOI/标题发现同篇本地副本；
- 阅读页「版本对照」把当前作业与另一个副本放进 `mode:'version'`；
- 两侧重新读取 MirrorDoc 的 `version.kind/label`，在论文栏显示 VOR/录用稿/预印本徽标；
- `buildVersionDiff` 对段落和标题做 LCS，输出 `added/removed/unchanged`；
- 浮窗两边分别显示版本标题与 jobId，段落可点回对应论文；
- 测试会先用真实同题作业写 VOR/预印本，再用完整文件快照恢复，避免测试残留。

## 7. 持久化

| 数据 | 位置 | 说明 |
|---|---|---|
| 工作台对话 | 浏览器 localStorage，key 含论文集合/模式/引用位置 | 刷新恢复；不跨设备承诺 |
| 对照表人工修订 | 浏览器 localStorage | 不覆盖原始模型表，导出时叠加 |
| 本地归档 | `$DSH_HOME/doraemon-paper-reader/compare-archives/` | 报告、表、批注、对话、引用结论；不内置云账号 |
| 版本核验 | 每篇 `mirrordoc.json` + `paper-summary.json` | 版本对象跟论文走 |
| 批注 | 每篇 `annotations.json` | 与单篇阅读共用 |

## 8. 验收口径

P1 完成不是“页面上出现了两个输入框”，而是以下链路均有实测：

1. 两篇真实论文全文同时渲染，引用、批注、翻译、术语、公式不退化；
2. 多篇批注能同一次发送，模型能按论文归属理解；
3. 七字段表每格可回 blockId；
4. 引用对照固定 A/B 角色，没有证据时降级；
5. 真实引用预览能回到引用处并打开双篇；
6. 同篇 VOR/预印本有可见版本标签与两列文本差异；
7. 概念图的事实/归纳界限可见；
8. 数据图每个点可回原文；
9. 桌面包能从应用内插件页安装、启用并在新会话打开；
10. L0、PDF 回归、L2 浏览器与 console 都通过。
