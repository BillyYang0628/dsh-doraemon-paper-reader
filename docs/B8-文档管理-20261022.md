# B8 文档管理

## 1. 目标与结果

B8 把原来的“上传后立即转义”单文件入口，扩展为持久文档库：

- 批量导入 PDF，但导入阶段不强制转义；
- 点击文档后再进入单并发转义队列；
- 相同 SHA-256 文件不重复保存；
- 不同物理文件保留为显式版本组；
- 支持搜索、状态筛选、排序和批量操作；
- 删除先进入可恢复回收站；
- 刷新和 Host 重启后状态仍可读取。

原有 `POST /import` 保持上传后自动转义，因此单篇 PDF 页签的上传、轮询、完成页和阅读页链路不变。

## 2. 数据模型

每个作业目录新增：

```text
library-entry.json
```

主要字段：

| 字段 | 含义 |
|---|---|
| `jobId` | 继续作为唯一文档标识，批注、引用、翻译和归档无需迁移 |
| `sha256` / `bytes` | 物理文件身份和大小 |
| `libraryStatus` | `imported / queued / converting / ready / failed / missing` |
| `metadata` | 标题、作者、DOI、arXiv、venue、year |
| `artifacts` | 原 PDF、MirrorDoc、摘要、原页和资源的完整性 |
| `importedAt` / `updatedAt` / `readyAt` | 生命周期时间 |
| `trashedAt` | 回收站时间，恢复时清空 |

旧作业没有 manifest 时，从 `paper-summary.json`、`mirrordoc.json`、原 PDF 和目录时间合成兼容视图。

## 3. 状态规则

| 状态 | 进入条件 |
|---|---|
| `imported` | PDF 已流式落盘并计算哈希，尚无 MirrorDoc |
| `queued` | 用户显式请求转义，已进入队列 |
| `converting` | 单并发转换器开始处理 |
| `ready` | MirrorDoc 已生成，可进入阅读页 |
| `failed` | 转义失败，可重试 |
| `missing` | 原 PDF 或完成态关键产物缺失 |

应用重启后：

- 已持久化的 `queued` / `converting` 不伪装为仍在运行；
- 状态转为可重试的 `failed`，错误说明为“转换进程因应用重启而中断”；
- `ready` 与 `imported` 保持原状态。

旧 `job.status` 的 `running / done / failed` 保留给现有加载页；文档管理读取新增的 `libraryStatus`。

## 4. API

| 接口 | 用途 |
|---|---|
| `POST /import` | 旧单篇流程，自动转义 |
| `POST /library/import` | 轻量入库，只落盘和计算 SHA-256 |
| `GET /library?view=manage` | 未折叠文档、版本组、回收站与状态统计 |
| `POST /jobs/:id/convert` | 单篇按需转义 |
| `POST /library/convert` | 批量排队 |
| `POST /library/trash` | 单篇或批量移到回收站 |
| `POST /library/restore` | 单篇或批量恢复 |

PDF 上传改为流式临时文件加增量 SHA-256。非 PDF、超过 200 MB 或中断上传会删除临时目录。

## 5. 页面

主界面新增“文档管理”入口，独立页签包含：

- 多文件选择与拖入；
- 总文档、待转义、处理中、可阅读、失败/缺失统计；
- 标题、作者、DOI、arXiv 或文件名搜索；
- 全部、待转义、处理中、可阅读、失败/缺失筛选；
- 最近更新、最近导入、标题排序；
- 单篇打开、开始转义、重试、移到回收站；
- 批量转义、批量移动、批量恢复和当前筛选全选；
- 回收站视图；
- 操作中提示、错误恢复与 `aria-live` 状态；
- 375px 卡片式重排和深色主题。

文档列表不加入吉祥物；空态使用现有 `stack-books` 资产。

## 6. 真实 DSH 回归

证据：

```text
工具/gen/B8-20261022/e2e/library-final/
```

使用 AgriEngineering 19 页真实 PDF 生成 10 份唯一副本，通过页面文件输入一次选择：

- 10/10 入库成功，全部保持 `imported`；
- 页面不冻结，导入后显示“新入库 10 篇”；
- 相同文件再次导入显示重复，不增加物理文档；
- 点击其中一篇后进入 `queued → converting → ready`；
- 完成后标题从文件名替换为论文真实标题、作者和 DOI；
- 点击“打开阅读”成功进入既有阅读页；
- 另一篇移到回收站后不出现在文档库，回收站可看到并恢复；
- 恢复后原 PDF 与批注存档仍在；
- 375px 无横向溢出；
- 深色模式截图通过；
- console/page errors 为 0。

另跑旧 `/import` 单篇真实 PDF 回归，确认兼容行为：

- 再次上传同一 PDF 仍创建独立新任务，不套用文档管理的哈希去重；
- 加载计时从 `00:02` 正常恢复；
- 阅读页 19/19 图片、5 个表格、2 条内容分隔线与 1 条算法内规则正常；
- errors 0。

Host 重启后再次查询同一批 10 篇：

```text
found = 10
ready = 1
imported = 9
failed = 0
```

说明未转义和完成态均从磁盘恢复，且没有伪造运行态。

测试生成的 10 个作业已在核对 `originalName` 前缀和 `jobId` 后清理。

## 8. 边界

- 回收站目前只支持恢复，没有“永久清空”入口；
- 不包含文件夹、标签、Zotero、云同步或 OCR；
- 不同 DOI/arXiv/标题在首轮轻量入库时只能按文件名展示，转义后才完成题录分组；
- 转义仍为单并发，优先保证 CPU、Python 和磁盘稳定；
- 批量转义是显式操作，不因批量导入自动触发。
