# 论文阅读器问题处理方案 v1

> 输入问题源：[`论文阅读器实测问题台账-v1.md`](论文阅读器实测问题台账-v1.md) 的 R-001～R-021。
> 本文负责排期、依赖和验收；单项问题的最新状态仍回维护在问题台账。
> 本文不改变任何功能代码，也不把“计划完成”写成“功能完成”。

## 1. 总体策略

这批问题不能按编号平均推进，因为依赖关系不同：

- R-002、R-007、R-004 是用户马上会遇到的功能阻断/死入口，先止血。
- R-001、R-003、R-010、R-014、R-015 是相对独立的展示和状态问题，可作为小步快跑批次。
- R-005、R-011、R-012、R-013、R-018 属于同一套 PDF 结构可靠性工程，必须共用测试语料、块账本和回归台。
- R-009 必须先提高候选召回，R-008 的排序和置信度才有意义。
- R-016、R-017 是问答基础契约，R-019 的模式只能在基础契约稳定后叠加。
- R-021 文档库是 R-020 多篇综述的输入基础，先建稳定文档管理，再调试多篇任务。

## 2. 前置门禁：先保存当前可回退基线

在修任何问题前先整理一次 Git 基线，避免当前大量未提交源码、测试、资产和文档互相覆盖。

建议提交批次：

1. `docs: 固化当前设计、决定和实测问题台账`
2. `test: 固化当前 L0/L2 回归与测试工具`
3. `feat: 固化现有插件功能与 UI 基线`
4. `assets: 加入透明角色、精灵图与小物件`
5. `chore: 清理可重建产物并确认发布包白名单`

退出条件：

- `git status` 中只剩明确不纳入提交的本地产物。
- `npm run verify` 通过。
- 当前桌面版可打开的插件版本有明确 commit 可回退。

## 4. B0 可复现基线

**目标**：把“用户看到了问题”变成“开发和测试能稳定复现”。

动作：

1. 固定 PDF 语料：
   - 当前 AgriEngineering AIoT 论文；
   - Sensors / Plague / PLOS 三篇现有回归样本；
   - arXiv HTML 一篇；
   - 至少一篇长表论文、一篇算法框论文、一篇双栏全宽图论文。
2. 每项失败记录：
   - PDF SHA、页码、blockId、表格/图号；
   - 请求 URL、payload 摘要、HTTP 状态；
   - 主题、视口宽度、DSH 页面在当前 tab/全屏的布局；
   - 改动前截图或录屏。
3. 新增最小测试入口：
   - `工具/e2e/navigation-state.mjs`：目录 sticky、tab 切换滚动恢复；
   - `工具/e2e/pdf-structure-audit.mjs`：原页 vs 中文页逐段审计；
   - `工具/e2e/qa-contract.mjs`：批注问答行为评分；
   - `工具/e2e/library.mjs`：文档管理、批量导入、按需转义。
4. 红灯优先：先写失败断言，再进入修复。

退出条件：

- P0 和 PDF 结构问题均至少有一个可重复 fixture。
- 没有 fixture 的问题只允许做“取证”，不允许声称修复。

## 5. B1 P0 止血

### R-002 拖动 PDF 后宿主遮罩卡死

方案方向：

- 在插件 pane 的捕获阶段统一接管 `dragenter/dragover/drop/dragleave`；
- drop 后显式通知/清理宿主全局状态；
- 覆盖拖入拖放区、拖入插件空白、拖出窗口、取消和窗口失焦。

退出条件：

- 桌面应用拖放全链通过。
- 所有中断路径均不残留遮罩。
- 原有点击选择入口不退化。

### R-007 引用蓝链 HTTP 400

方案方向：

- 建立引用 linkID → blockId → reference metadata → resolve request 的可追踪链路；
- 400 记录请求体与服务端错误码；
- 把“引用异常”和“无合法全文”分开处理。

退出条件：

- 当前测试 PDF 蓝链逐条点击，400 为 0。
- 单条、逗号、区间、缺失参考文献均有测试。

### R-004 “原版 P.n”死入口

方案方向：

- 先验证 `source-pages/page-XX.png` 是否存在及 Electron 是否能打开；
- 决定“打开原始 PDF 的 `#page=N`”还是“打开源页图像”；
- 资源缺失时隐藏入口或显示明确不可用状态。

退出条件：

- page 1、page 10、最后一页和参考文献页均可打开。
- 不再存在可点击但无反应的控件。

## 6. B2 版式与阅读连续性

包含：R-001、R-003、R-010、R-014、R-015。

处理顺序：

1. R-001 暗色主界面插画底与署名。
2. R-003 抄写插画去框、去说明、放大到 2–3 倍并重排。
3. R-010 阅读页 pane 宽度比例曲线。
4. R-014 sticky 目录动态 offset。
5. R-015 阅读 scrollTop 保存/恢复。

数值门禁：

- 1920、2560、3440 宽度；
- DSH 全屏主对话:插件约 4:6；
- 375px 窄屏；
- 亮/暗主题；
- `prefers-reduced-motion`；
- 插画与文案不相交；
- tab 切换后位置偏差不超过一个正文块。

## 7. B3 PDF 结构工程 I

包含：R-005、R-011、R-012、R-013。

### 7.1 先建立“块账本”

每个源文本区域记录：

- `page/bbox/sourceIds`
- 识别类型：paragraph/heading/list-item/algorithm/separator/table/figure/equation/reference
- reading order
- 父块/子步骤
- 翻译单位 ID
- 中文块与原文块对应关系

### 7.2 原页 vs 中文页对照台

同一页面左右显示：

- 左：PDF 原页图像，可高亮 bbox；
- 右：插件中文/对照阅读页；
- 中间：block 列表和类型/顺序标记。

人工只需判断：正确、漏块、重复、错序、错型、错译、锚点错位。

### 7.3 首轮算法修复

1. 新增独立 `algorithm` block：
   - 题注；
   - `BEGIN/END`；
   - 编号步骤；
2. 段落内 run-in heading 与正文字号分离。
3. 内容分隔线转为 separator block；表格内部线不进入正文。
4. 禁止 `BEGIN/END`、列表步骤、表格行进入目录。

退出条件：

- Algorithm 1 在原文、中文、对照三态结构一致。
- 正文字号跳变有明确 block 原因。
- 内容分隔线位置与原文一致。
- 每个修复都有 fixture 和回归项。

## 8. B4 PDF 结构工程 II：长表与跨页表

包含：R-018，并继续 R-005/R-011。

动作：

1. 表格检测从“单个 bbox”升级为“表题—表头—主体—续表—脚注”的逻辑表；
2. 检查 bbox 漏掉后半表、跨栏、跨页和稀疏无框表；
3. `table` block 内禁止被 reconcile 二次切成 paragraph；
4. 表格完整性报告：
   - 原表行数；
   - 解析行数；
   - 缺失/重复/退化行；
   - 跨页段数；
   - 数字校验结果。
5. 结构不完整时保留整表原图并明确告警，不能“半表 + 半段落”静默混排。

退出条件：

- 长表、跨页表、无框表、旋转表分别通过。
- 中文表格只在结构完整且数字通过时显示。

## 9. B5 候选检索与引用体验

顺序必须是 R-009 → R-008。

### B5.1 多路召回

- DOI/arXiv 精确路径保留；
- OpenAlex 题录搜索；
- Crossref bibliographic query；
- arXiv 标题搜索；
- 标题变体、第一作者+年份、作者+venue 查询；
- 引文上下文关键词轻量重排；
- DOI/arXiv/规范化标题去重。

建立至少 30 条真实引用的离线基准集，评估 Recall@5、Top-1、Top-3。

### B5.2 排序与解释

候选首位采用综合匹配分：

- 标题相似；
- 作者/年份/venue；
- DOI/arXiv；
- 摘要/关键词与引用句重叠；
- 是否已出现在参考文献表。

UI：

- 最可能项置顶并使用不同颜色/边框；
- 显示高/中/低置信度和依据；
- 不只依赖颜色；
- 多个高度相似项允许并列提示，不强制唯一。

## 10. B6 批注问答契约

包含：R-016、R-017。

建立统一回答契约：

1. 第一段直接回答用户问题。
2. 解释论文的概念、证据、推理和上下文。
3. 不默认审稿；批判性只放末尾“局限/需注意”。
4. 没有明确问题时，默认讲解、归纳和结构化总结。
5. 具备联网能力时可补充外部背景，但必须区分：
   - 论文原文；
   - 外部资料；
   - 模型分析。
6. 长回答必须经过理解后重组，禁止逐句同义改写。

建立固定问题集：

- 术语解释；
- 方法理解；
- 图表读数；
- 段落在全文中的作用；
- 寻找灵感；
- 明确要求批判；
- 明确要求只根据原文。

评分：

- 是否先答问题；
- 是否准确；
- 是否有理解后结构；
- 复读比例；
- 无端批判比例；
- 原文/外部证据边界。

## 11. B7 目录与模式化

### R-006 语义目录

依赖结构块稳定后：

- 通读论文，按研究背景/方法/实验/结果/局限等分组；
- 每组生成短中文概括；
- 原文、中文、对照三种模式同步；
- 保留原文标题作辅助；
- 算法/表格/正文碎片不得进目录。

### R-019 研究/灵感模式

在 B6 契约稳定后：

- 目录下增加两个按钮；
- 研究模式注入用户研究方向，只在回答末尾增加关联分析；
- 灵感模式提取创新点并做论文查新；
- 无联网时明确“未查新”；
- 默认未启用，保持精读理解语义。

## 12. B8 文档管理

包含 R-021。

第一阶段先做数据模型：

- `imported / queued / converting / ready / failed / missing`
- SHA/DOI/标题/作者/批注数/版本关系
- 原 PDF、MirrorDoc、source-pages 的完整性

第二阶段做页面与批量导入：

- 独立文档管理页；
- 批量选择/拖入；
- 导入时不强制转义；
- 点击未转义 PDF 才排队；
- 单文件失败不影响整批；
- 重复文件/版本不静默覆盖。

第三阶段做批量操作：

- 批量重试；
- 批量后台转义（显式选择）；
- 删除前显示批注/归档影响范围。

退出条件：

- 10 个 PDF 批量导入不冻结。
- 刷新/重启后状态保留。
- ready 直接阅读，imported 点击后转义。

## 13. B9 多篇综述

依赖 B4、B6、B8。

先重新定义三条核心旅程：

1. 2 篇方法对照；
2. 3 篇研究缺口；
3. 从证据表形成综述笔记/报告。

真实任务集：

- 同题不同方法；
- 同方法不同数据；
- 结论冲突；
- 综述+原创研究；
- 不可比论文负例。

最终验收不是页面出现双栏，而是：

- 系统能判断论文是否可比；
- 每个事实有 blockId；
- 归纳是跨论文关系，不是逐篇摘要拼接；
- 能形成可验证研究缺口；
- 报告无无出处事实；
- 用户能据此推进真实研究任务。

## 14. 每批交付门禁

每个批次结束必须提交：

1. 改动文件清单；
2. L0/L1/L2 红绿结果；
3. 桌面 DSH 真实路径证据；
4. 亮/暗、375px、相关状态截图；
5. 未跑项与已知边界；
6. 问题台账状态更新；
7. 决定台账与项目索引更新；
8. 清理临时 job、端口和进程。

## 15. 推荐立即开始

**先执行 B0，然后 B1。**

原因：

- B0 给后续所有修复提供可重复证据；
- B1 只处理 P0 阻断和死入口，风险低、收益直接；
- B2 可在 B1 后小步并行；
- PDF 结构工程从 B3 正式启动，但要成为持续主线，不能被其它 UI 工作长期压后。
