# PDF 审计实验 03：B3 结构收口

## 1. 本轮目标

按 [`B3结构收口执行方案-v1.md`](B3结构收口执行方案-v1.md) 的“审计先行”规则，验证并修复：

本轮不处理 B4 的表格单元格金标和中文翻译语义。

## 2. 审计假设

新增三条可证伪诊断：

1. `reading-order.cross-column-line`：全宽视觉行仍跨过双栏栏缝；
2. `separator.unrepresented`：检测到内容水平线，但 MirrorDoc 没有 `separator` 或特殊块 `visualRules`；
3. paragraph 字号聚类探针：正文块中是否存在接近标题字号、但被并入 paragraph 的短行。

只有前两条在现有语料中命中后才修改算法。第三条用于验证 R-012，未命中时不制造新规则。

## 3. 实验 A：Twitter 综述跨栏混排

### Before

审计目录：

```text
工具/gen/B3-20261022/audit-before/twitter-review-special/
```

结果：

- `reading-order.cross-column-line = 27`；
- 页面：1、4、7、8、13；
- 代表证据：
  - p4 `p004-f060`：左栏搜索式与右栏 documenting phase 拼成一行；
  - p4 `p004-f062`：左右栏内容形成 116.56pt 的栏缝；
  - p7 `p007-f076`、p8 `p008-f027`、p13 `p013-f054` 均存在同类错误。

根因：

- 纵向空白检测要求整页持续空白；全宽表/图占据栏缝时无法发现正文双栏；
- 原 word-start fallback 只在页面中点附近寻找完全相同的起点；
- Twitter 右栏起点实际约在页宽 50%～52%，未落入旧锚点条件；
- 上层全宽表结束后，代码仍把下方正文当作 `full`。

### 算法调整

- 新增 `_infer_column_structure()`：
  - 在页宽 43%～65% 内寻找重复右栏起点；
  - 输出栏缝与右栏稳定起始 y；
  - 上层全宽对象保留在 `full`，只对下方正文分栏。
- 新增行级诊断：`maxInternalGap`、`internalGapCount`、`maxCenterGap`。

### 回归发现的新问题

分栏后，`[AND]` 在 p4/p5 重复出现。reconcile 的 running-head 清理把长度 ≤60 的重复 paragraph 直接删除，导致：

- p004-l012；
- p005-l047；
- `coverage.missing-content = 1`（两条 sourceId）。

这是审计发现的真实回归。修复为重复 running-head 的最短长度设为 12，短搜索运算符继续保留。

### After

审计目录：

```text
工具/gen/B3-20261022/after-column-v3/twitter-review-special/
```

结果：

- `reading-order.cross-column-line：27 → 0`；
- `coverage.missing-content：1 → 0`；
- 文本覆盖率 100%；
- `[AND]` 在 MirrorDoc 中保持为独立段落；
- 新回归：Twitter Figure 11 → 12，补回原漏识别的真实 Figure 12。
