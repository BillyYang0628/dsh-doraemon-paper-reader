# 开发流程

> 参考「托蕾妮小程序」那套跑通了两个月的流程，按**插件开发**这个形态改写。
> 硬规则在 [`AGENTS.md`](../AGENTS.md)，决定记录在 [`决定台账.md`](决定台账.md)。

## 1. 状态阶梯（没有证据不许往右移）

```
Planned → Implemented → Self-Tested → Integrated → Accepted
```

| 状态 | 含义 | 升级需要什么证据 |
|---|---|---|
| **Planned** | 已写进功能框架/里程碑 | 文档里有条目 |
| **Implemented** | 代码写完，能加载 | 代码存在 + 能在 `dsh dev` 日志里看到加载 |
| **Self-Tested** | 自动化测试跑绿 | L0/L1 测试红绿结论（贴命令与结果） |
| **Integrated** | 在真实 DSH（dev profile）里跑通端到端 | L2/L3 结论 + 截图（界面类） |
| **Accepted** | 用户验收通过 | 用户的明确确认 |

**禁止**：把"代码写完"说成"做好了"；把"单测绿"说成"能用"；把"我这边看着对"说成"验收通过"。

## 2. 里程碑（与 [`功能框架-v0.md`](功能框架-v0.md) §11 一致）

| 阶段 | 内容 | 完成判据 |
|---|---|---|
| M0（已完成） | DSH 双端就绪、中文、磁盘策略、API Key、开发 profile | `dsh dev` 能起、模型能答 |
| M1 阅读闭环 | 阅读器页 + 打开本地 PDF + 选文提问 + 对照视图 | 一篇论文能对照读、能选文提问并跳回页码 |
| M1.5 获取与镜像 | 标识符解析 + arXiv/ar5iv HTML 摄取 + `MirrorDoc` + 版本戳 + 引用蓝链起步 | 给 DOI/arXiv 号，秒级出可读镜像，界面显式标注版本 |
| M2 词典划词 | 词级查询（离线词库 + 语境义） | 选中单词即出词性/音标/义项/本句含义 |
| M3 批注勾画 | 锚点模型 + 高亮图层 + 持久化 + 列表/导出 | 关掉重开批注仍在，可跳转，可带进问答 |
| M4 生词本 | 一键入库、复习、朗读 | 生词可复习，闭环成立 |
| M5（可选） | 多篇对比、外部文献库对接 | 按需 |

**一个阶段内部**再切成"能独立验证的小步"（例如 M1.5 第一步只做 `resolve_paper` 工具 + L0/L1 测试）。

## 3. 单次任务的循环

```
读文档 → 声明计划与判据 → 实现 → 自测（L0/L1）→ 在 dev profile 实测（L2/L3）
      → 收证据（截图/日志/红绿）→ 更新决定台账与项目索引 → 提交
```

- **动手前**：说清"这次要改什么、怎么验证、影响哪些不变量"；涉及功能取舍的先写进决定台账。
- **动手时**：一次只推进一个可验证的小步，别把三件事混在一次提交里。
- **收尾时**：四件交付物照 `AGENTS.md` §7 给（改了什么 / 验证结论 / 未跑项 / 截图）。

## 4. 测试与回归的分层

| 层 | 跑什么 | 命令 | 要不要 DSH 在跑 |
|---|---|---|---|
| **L0** 纯逻辑 | 解析、匹配、锚点、纯函数模块 | `npm test` | 不需要 |
| **L1** 宿主半区 | 工具注册与输出、路由、落盘结果 | `dsh --profile headless "<任务>"` 或临时 profile | 不需要交互界面 |
| **L2** 浏览器半区 | 页签、浮层、批注 UI、设置卡片；PDF 上传/后台抄写/阅读页；摘要批注；翻译/对照；公式/表格/整篇复核；回答回跳；版本核验；**对照工作台 v2（双论文全文/批注/蓝链/右侧对话/产物浮窗/公式 SVG/32 列网格）**；**真实引用全链**；**文档管理批量导入/按需转义/回收站**；**B9 方法对照/研究缺口/证据报告**；**P3 知识检索/引用图/导出/阅读档案** | `dsh --profile dev --no-open --port <空闲端口>` + `main-interface.mjs`、`pdf-import.mjs`、`library.mjs`、`survey-modes.mjs`、`knowledge-center.mjs`、`summary-annotation.mjs`、`translation.mjs --job <jobId> [--review]`、`answer-link.mjs --job <jobId>`、`version.mjs --job <jobId>`、`formula-correction.mjs --job <jobId> --job-dir <dir>`、`compare.mjs --with-llm`、`multi-annotation.mjs`、`citation-chain.mjs`（Edge + `playwright-core`，**不下载内核**；见 D-024 / D-031 / D-048 / D-049 / D-050 / D-052 / D-053 / D-060 / D-099 / D-100 / D-101） | 需要 |
| **L3** 端到端 | 工具 ↔ 模型 ↔ 界面整链 | 用 DSH SDK（`--profile sdk`）脚本驱动会话 | 需要 |

规矩：

1. **联网用例要能离线跑**——真实响应先落盘成 fixture（放 `test/fixtures/`），避免"今天通明天红"。
2. **回归脚本不许写死 id / DOI / 路径**：命令行参数 → 自动挑选 → 现造 fixture。
3. 视觉判断只作辅助：能用数值断言的（文本、坐标、状态）就不要只靠截图（`AGENTS.md` K5）。
4. 模型相关用例：能用 **本地假上游（stub）** 就先别烧真 key；真端点的验证单独列出并注明日期。

## 5. 改动生效方式（改完什么时候能看到效果）

| 改的是 | 要做什么 | 大约耗时 |
|---|---|---|
| `src/*.js`（宿主半区） | 重新加载：**重启 `dsh dev`**（`link:` 安装不需要重新发布） | 秒级 |
| `test/*` | 直接 `npm test` | 秒级 |
| `cordis.patch.yml` | 重启 profile；**patch 变化要确认组合树**（`--dump-config`） | 秒级 |
| `package.json`（依赖 / `dsh` 字段 / `exports`） | 重新 `dsh plugin --profile dev add link:...` | 秒级 |
| 技能文件（`.dsh/skills/**/SKILL.md`） | 目录 watcher 会观测到变更，**不需要重启**；改完直接让下一次会话重新列技能 | 秒级 |
| 浏览器半区（`src/client.js`，单文件无构建） | 重启 profile 或刷新页面（`dsh` 按文件 mtime/size 换 rev，不吃旧缓存） | 秒级 |
| 用户日常的 `web` / `desktop` profile | **不在开发流程内**，等验收后单独确认再装 | — |

> 一句话原则：**开发期只动 `dev`；任何影响日常 profile 的动作都要单独说、单独确认。**

## 5.1 技能相关改动的验证（L1 就能做）

技能是否被正确加载，不用开界面也能验：

```powershell
# 官方随包技能（headless 需要 overlay 才可见，见 AGENTS.md §6）
dsh --profile headless --patch 工具\dev\official-skills.overlay.yml "用 skill 工具列出你能看到的技能名，一行一个"

# 项目级技能（rank 100：<项目>/.dsh/skills，headless 默认就能看到，无需 overlay）
dsh --profile headless "列出你当前可用的技能名称"
```

判定标准：清单里出现目标技能名即为接线成功；**清单里没有就报"未见"，不要用"应该已经加载"含糊过去**。

## 6. 验收定义（DoD）

一个阶段算完成，必须同时满足：

1. 功能在 `dev` profile 里**实际可用**（不是"应该能用"）；
2. 有**红/绿明确**的测试结论，且新增逻辑有对应测试；
3. 界面类改动有**并排对比截图**；
4. `docs/决定台账.md`、`docs/项目索引.md` 已更新（含日期）；
5. 未跑项已列出并说明原因；
6. 工作区干净（`git status` 无意外残留），无遗留进程/端口/临时文件。

## 7. 版本与发布（暂时不做，先有规则）

- 现阶段：`private: true` + `link:` 安装，**不发布**。
- 真要发布 npm 时，逐项确认：
  1. 版本号按语义化递增，`peerDependencies` 的 DSH 范围与实际测过的版本一致；
  2. `files` 白名单核对（新增目录容易漏）；
  3. README 与 `docs/项目索引.md` 同步；
  4. 在**干净的 profile** 上按普通用户路径装一次并跑通（不能只在开发机上验证）；
  5. DSH 升级后跑一遍回归清单，确认 peer 校验仍通过。
- 发布前如果涉及第三方代码复用：`THIRD_PARTY_NOTICES` 与许可声明必须齐（参考 `paper-translation` 技能的做法）。

## 8. 与其他 DSH 插件共存（每次都要验）

装我们的插件前后：

```powershell
dsh --profile dev --dump-config > 工具\gen\dump-before.txt
# 安装 / 更新我们的插件
dsh --profile dev --dump-config > 工具\gen\dump-after.txt
```

用 diff 确认**只有新增行**，没有覆盖或改写别人的条目。
将来与第三方插件（如 `paper-reader`）同时安装时，这条必须重新跑一遍。
