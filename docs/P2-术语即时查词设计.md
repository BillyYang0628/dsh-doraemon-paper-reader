# P2 论文术语即时查词设计

## 1. 目标

选中论文里的单词、缩写、专业术语或短语，解释它**在当前句子和当前论文语境中**是什么意思。

这不是英语学习功能：

- 不收藏生词；
- 不建生词本；
- 不记录掌握度；
- 不做标签、SRS、背诵或学习计划；
- 不要求发音和音标。

查询结束即结束。宿主只保留当前进程内的短周期查询缓存，用于避免同一句里的同一个词重复调用模型；缓存不落盘，重启即清空。

## 2. 用户流程

1. 在单篇阅读页或双篇论文栏选中 `RFID`、`IncA/C` 等词；
2. 选区浮层出现「查词」和原有批注入口；
3. 点「查词」，出现轻量卡片；
4. 卡片显示本文语境义、论文内全称、同缩写多候选、必要的模型补充、当前句、页码/章节/blockId；
5. 可点「定位原段」，或按 Esc / 关闭按钮收起；
6. 不新增批注，不发送到主对话。

## 3. 查询分层

### 3.1 论文内确定性证据

优先查找：

- 当前已保存术语表里的同名词条；
- `full name (ABC)` 形式的括号定义；
- `ABC full name` 形式的缩写表/参考文献式定义。

这部分由 `src/terms.js` 完成，不调用模型。句界切分会跳过 `e.g.`、`i.e.`、`et al.`、`Fig.`、`Eq.` 等常见缩写点；同一缩写最多保留 6 个候选全称，优先当前段定义，并在出现多个候选时明确提示人工核对。

### 3.2 模型语境解释

只有缺少可靠中文解释时才调用模型。输入只包含：

- 选中词；
- 当前句；
- 当前段；
- 章节；
- 论文标题；
- 已命中的论文内缩写定义或术语表译名。

模型输出固定 JSON：

```json
{
  "kind": "word|phrase|acronym|identifier|symbol|unknown",
  "expanded": "论文内全称",
  "contextMeaning": "本文语境下的中文解释",
  "generalMeaning": "可选的模型补充",
  "roleInSentence": "在句中的作用",
  "confidence": "high|medium|low|unknown",
  "warnings": []
}
```

没有把握时必须返回低置信或「未能可靠确定」，禁止编造缩写全称。

### 3.3 降级

- 术语表已命中：直接返回术语表译名，高置信，不调用模型；
- 论文内只有全称、模型失败：返回全称并明确“没有可靠中文语境解释”；
- 没有术语表、没有全称、模型也不可用：显示查词失败，不伪造释义。

## 4. 界面

查词卡是一个临时浮层，不占新页签：

- 标题：选中词；
- 标签：词型、置信度、来源（论文术语表 / 模型语境解释）；
- 主体：本文语境义；
- 补充：论文内全称、模型补充、句中作用；
- 证据：当前句；
- 底部：页码、章节、blockId、定位原段；
- 关闭：×、Esc、切走论文。
- 窄屏：宽度 ≤600px 时自动切换为底部全宽卡片；颜色全部使用宿主主题 token，暗色主题实测通过。

单篇阅读页和双篇 `PaperPane` 共用 `TermLookupCard`。

## 5. 接口

```text
POST /doraemon-paper-reader/api/jobs/<jobId>/term-lookup
```

请求：

```json
{
  "term": "RFID",
  "blockId": "b0012",
  "before": "IoT system based on ",
  "after": " technology"
}
```

宿主重新读取当前 MirrorDoc 和段落，不接受前端直接提交任意“论文事实”。`__meta_abstract` 支持摘要选区。

## 6. 数据边界

| 数据 | 是否落盘 | 说明 |
|---|---|---|
| 查词结果 | 否 | 进程内 Map，最多 200 条，重启清空 |
| 用户生词库 | 不创建 | 本阶段没有该数据模型 |
| 收藏/标签/掌握度 | 不创建 | 明确不在范围 |
| 当前论文术语表 | 只读或临时抽取 | 查词不会创建 `glossary.json` |
| 现有批注 | 不修改 | 查词和批注是两条独立动作 |
