## 3. 问题详情

### R-001 深色主页面：角色插画背景与署名

**严重度：P2｜类型：视觉一致性 / 文案**

**实测现象**

1. 深色主题下，主界面右侧角色插画仍坐在一块偏灰黑色的贴纸底上，与页面暖金/深海军蓝层次不协调。角色资产本身是透明的，问题位于外层容器。
2. 插画下方文案为“小的我 · 大肥鱼”，用户要求改为“在下大肥鱼，请指教”。

**证据**

- [深色主界面截图](../工具/gen/实测问题-20261021/dark-home-mascot-background.png)

**当前实现线索（仅供定位，不是修复结论）**

- 主界面插画外层使用 `.dpr-mascotSticker`。
- 深色下该容器背景由 `color-mix(... var(--dpr-warn) ... var(--dpr-surface-raised))` 派生，实测形成灰黑/棕灰底。
- 当前文案键为 `home.mascotCaption`。

**期望**

- 插画不再出现与深色页面割裂的灰黑矩形贴纸底；容器要么完全融入页面，要么使用与深海军蓝卡面一致的协调层级。
- 署名改为“在下大肥鱼，请指教”；中英文资源键集保持同步。
- 浅色主题现有已认可观感不能被无意改坏。

**验收**

- 亮色/暗色主界面并排截图。
- 插画周边无大面积灰黑方底；容器和页面背景明度差可控。
- 中英文文案正确，alt 仍描述角色动作。

### R-002 拖动 PDF 后宿主遮罩卡死

**严重度：P0｜类型：拖放事件 / 宿主边界**

**复现**

1. 在本地 DSH 桌面应用中打开插件 PDF 页面。
2. 将 PDF 从资源管理器拖入插件的拖放区域。
3. 文件已经被选中或进入导入流程，但 DSH 宿主的全屏“文件或图片拖动到此处即可添加”遮罩留在最上层。
4. 下层插件仍可点击使用，但遮罩不会自动消失。

**证据**

- [卡死现场截图](../工具/gen/实测问题-20261021/drag-overlay-stuck.png)

**影响**

- 阻断正常导入流程，是桌面版发布的 P0 问题。
- 用户只能关闭/重启页面或窗口，无法通过插件自身操作恢复。

**当前实现线索（待验证）**

- 插件只在 `.dpr-drop` 上对 `dragOver`、`dragLeave`、`drop` 调用 `preventDefault()` / `stopPropagation()`。
- 宿主遮罩由 DSH 全局拖放机制维护；若 `dragenter/dragover` 已进入宿主状态，而插件边界没有在捕获阶段统一清理，宿主可能收不到匹配的 dragleave/drop 收尾。
- 需要同时验证：拖入拖放区、拖入插件页空白处、拖出窗口、拖入后取消、目录/多文件等路径。

**期望**

- 文件进入插件有效拖放区后由插件接管，宿主全局遮罩不出现，或出现后必定在 drop/dragend/dragleave/Escape 时消失。
- 不允许通过修改宿主安装文件解决；必须使用插件自身可承担的 DOM/事件边界。
- 文件选择、点击选择、拖放、取消都必须恢复同一可用状态。

**验收**

- 桌面应用真实拖入测试：PDF → 选中文件 → 开始抄写全链通过。
- 拖入后取消、从外部拖入插件空白区、拖出窗口、窗口失焦后，不残留遮罩。
- 原有按钮点击选择 PDF 保持正常。
- console/pageerror 为 0；不依赖手动刷新。

### R-003 抄写页插画框、说明文字与尺寸

**严重度：P1｜类型：插画 / 布局**

**实测现象**

1. 插画外侧仍有一圈浅蓝色/浅色卡片框，用户怀疑是旧插画容器没有删干净。
2. “大肥鱼正在一页页翻书”说明文字仍在插画下方。
3. 插画只有约 `92px`，用户期望至少放大到当前的 2–3 倍。
4. 放大后需要重新设计加载页排版，避免与标题、文件名、计时和阶段文字重叠。

**证据**

- [加载页现状](../工具/gen/实测问题-20261021/loading-illustration-frame.png)

**当前实现线索（待验证）**

- 透明角色已经清掉 `<img>` 自身背景，但外层 `.dpr-mascotSlot` 仍保留表面底色、边框、点阵背景和 `::before` 虚线框。
- `.dpr-slotNote` 仍渲染 `import.animationSlot` 文案。
- 当前加载态图面尺寸为 `92px`，左栏宽 `112px`。

**期望**

- 移除插画外层残留的浅色卡片框/虚线框，或明确改为与页面无缝融合的视觉承托。
- 删除“大肥鱼正在一页页翻书”说明文字；如仍需状态说明，只能使用业务阶段文案，不重复描述动画。
- 插画按 2–3 倍目标放大；建议在实现阶段先比较 `184 / 230 / 276px` 三档，不在本台账直接定死。
- 大图出现后，优先考虑上下结构或扩展左栏宽度，确保标题、文件名、计时、阶段列表都有稳定空间。
- 375px 窄屏有单独降级方案，不产生横向滚动或遮字。

**验收**

- 静态、running、done、failed 四态插画位置尺寸一致。
- 大图与右侧文案盒模型不相交；至少保留当前规则要求的 12px 实际间距，建议 16px 以上。
- 375px、亮/暗主题和 `prefers-reduced-motion` 全部通过。
- 加载/成功动画仍按现有帧序播放，不因放大糊掉像素边缘。

### R-004 “原版 P.n”入口不可用

**严重度：P1｜类型：功能真实性 / 深链**

**实测现象**

用户点击块旁“原版 P.n”后无法跳转到本地 PDF 对应页面，怀疑该功能没有实现。

**当前实现线索**

- `src/client.js` 中存在 `sourcePageUrl(jobId, page)`。
- 当块有页码时，`pageBadge(page)` 会渲染 `<a href=... target="_blank">原版 p.n</a>`。
- 因此代码并非完全没有入口；当前问题更可能是源页资产缺失、URL 错误、Electron 新窗口/资源打开受限，或页号映射不匹配。以上均待验证。
- 当前 URL 指向 `jobs/<jobId>/source-pages/page-XX.png`，不是 PDF 文件的 `#page=n` 深链。

**期望：二选一，必须做真**

方案 A：保留功能并确保点击能打开：

- 优先打开本地 `original.pdf#page=N`，或打开对应源页图像；
- 页码必须来自块在原始 PDF 中的真实 page；
- 资源缺失时不得留下可点击死按钮。

方案 B：若短期不实现，则隐藏或禁用并明确说明；不能出现“看起来能点、点击无反应”。

**验收**

- 桌面应用中点击每一类块（标题/正文/图表/公式/参考文献）的页码入口均成功。
- 至少验证 page 1、page 10、最后一页和参考文献页。
- 资源 404、无 source-pages 的 HTML 作业、旧 job 重开都不出现死链接。
- 跳转后返回阅读位置不丢失。

### R-005 PDF 结构抽取：算法框/表格化信息被误当正文

**严重度：P1｜类型：结构解析 / 阅读顺序 / 翻译质量**

**2026-10-21 审计实验记录**

- 完整实验见 [`PDF审计实验01-AIoT-20261021.md`](PDF审计实验01-AIoT-20261021.md)。
- before：`BEGIN/END` 进入目录，12 步压成 `b0106` 普通段落。
- after：`b0078` 为单一 `algorithm`，12 个 step 均带 `number/depth/sourceId`。
- 控制流深度依次为 `0,0,1,1,1,2,1,2,2,1,1,0`。
- `npm test`、四篇 PDF 回归与结构审计均通过；待用户在实际阅读页验收。

**2026-10-22 B3 收口记录**

- Algorithm 1 外侧两条边界线已转为 `separator`，题注与步骤之间的线已进入 `visualRules`；
- AIoT 真实阅读页 `contentRules=2`、`algorithmRules=1`，errors 0；
- 全量回归中 IoT 3 个算法共得到 5 条边界 separator，结构审计无 error。

**样本位置**

测试论文第 10 页，Algorithm 1：IoT-based plant management system 伪代码。

**证据**

- [论文第 10 页原版](../工具/gen/实测问题-20261021/paper-page10.png)

**原文结构**

- 有一个独立题注：`Algorithm 1. Pseudo-code summarizing ...`
- 外层有明确的 `BEGIN ... END`
- 内部是 1–12 条带缩进和嵌套关系的步骤
- 原文边框/版式将其与正文明确分开

**当前错误结果**

- `BEGIN` 和 `END` 被错误放进左侧目录。
- 12 条步骤被压成一段普通正文。
- `WHILE / IF / ELSE IF / END IF / END WHILE` 的层级与缩进丢失。
- 中英文阅读时不符合结构化算法块的阅读习惯。

**这不是单页修补问题**

需要建立“多 PDF 对照结构回归”，用视觉原页与 HTML/中文翻译页逐段核对。至少覆盖：

| 类型 | 必测样本 |
|---|---|
| 单栏正文 | 普通段落、标题、脚注 |
| 双栏正文 | 跨栏标题、左右栏顺序 |
| 全宽图 | 两栏中间的 page-wide figure |
| 表格 | 普通表、跨页表、旋转密集表 |
| 算法框 | BEGIN/END、IF/WHILE、编号步骤、缩进 |
| 公式 | 行内公式、编号公式、多行公式 |
| 参考文献 | 编号、跨页、引用回链 |

**算法块目标表示（示例，不锁实现）**

```json
{
  "type": "algorithm",
  "label": "Algorithm 1",
  "caption": "Pseudo-code summarizing the operations ...",
  "steps": [
    { "number": 1, "depth": 0, "text": "Initialize Firebase, Wi-Fi, sensors, and actuators" },
    { "number": 2, "depth": 0, "text": "WHILE TRUE DO" },
    { "number": 3, "depth": 1, "text": "Read all sensor data ..." }
  ]
}
```

具体数据模型可调整，但必须保留：算法题注、外层 BEGIN/END、步骤编号、嵌套深度、原页 blockId/page、翻译对应关系。

**验收**

- 算法块不进入普通正文流，不进入目录。
- `BEGIN/END` 只在算法块内显示。
- 中文翻译保留编号、层级和关键字含义；对照模式可同时看到原文步骤与译文。
- 原页定位能回到第 10 页对应块。
- 每个测试 PDF 形成一份“原页 vs 转义页”问题表，记录漏块、顺序错误、类型错误和翻译错位。

**根因分类要求**

后续修复必须把错误归类到算法层，而不是只对当前 PDF 打补丁：

1. 字符/行/边框识别错误；
2. 栏顺序/阅读顺序错误；
3. block 类型分类错误；
4. 表格/算法结构重建错误；
5. 翻译单位与源块锚点错误；
6. 目录/摘要与正文结构脱节。

### R-006 阅读页左侧目录可读性、语言与语义层级

**严重度：P1｜类型：导航 / 本地化 / 信息架构**

**实测问题**

1. 左栏当前仅 `132px`，目录项字号 `9px`，长标题被省略，无法看清。
2. 阅读器切到中文后，目录仍显示英文原题，不随语言模式切换。
3. 目录目前是直接从 `doc.blocks` 的 heading 抽取，并没有“通读后分段归类再概括”。
4. 章节较少或标题本身不清晰时，无法帮助用户快速理解论文结构。

**证据路径**

- 当前代码：`outlineItems = doc.blocks.filter(type === 'heading')`
- 当前 CSS：`.dpr-readerLayout` 左栏 `132px`，`.dpr-readerOutlineItem` 字号 `9px`

**期望**

- 目录先由插件通读论文，再形成 2 层左右的语义结构：
  - 一级：研究背景、方法、实验、结果、局限、结论等；
  - 二级：每部分用几个词到一句短句概括，并保留原文 heading 作为辅助信息。
- 中文模式显示中文概括；对照模式可中文主标题 + 英文原文副标题。
- 目录宽度、字号和行高可读，不能只靠 tooltip 补全。
- 目录项仍可定位原文 blockId/page。
- 算法、表格、图表等结构块不能误入目录。

**验收**

- 中文/原文/对照三种语言模式切换后，目录同步更新。
- 桌面常规宽度和 375px 均有可读方案；窄屏可改为横向滚动或抽屉，但不能压缩到不可读。
- 目录条目不是原文标题的机械复制；至少包含一段可验证的语义概括。
- 目录生成失败时回退原文 heading，并明确标记回退状态。

### R-007 引用蓝链出现 HTTP 400

**严重度：P1｜类型：引用解析 / 错误恢复**

**实测现象**

- 阅读页部分 `[n]` 蓝链点击后返回 HTTP 400，无法进入引用预览或后续对照。
- 不是所有蓝链都失败，说明要优先定位特定引用编号、范围、blockId 或 payload 形态。

**期望**

- 合法的单条引用 `[1]`、逗号引用 `[1,2]`、区间引用 `[1–3]` 都能进入正确链路。
- 上游元数据缺失、参考文献条目异常或无法合法获取全文时，显示清楚的降级卡片，不把 HTTP 400 原样甩给用户。
- 400 必须有结构化诊断：页面 blockId、引用编号、请求 URL、请求体摘要、服务端错误码和可恢复动作。

**验收**

- 对测试 PDF 的所有蓝链逐条点击，统计成功、metadata-only、合法失败和 400。
- 400 数必须为 0；业务性失败使用明确文案与恢复路径。
- L2 覆盖单条、逗号、区间、跨年份引用和参考文献缺项。

### R-008 候选论文排序、突出与置信度

**严重度：P1｜类型：检索结果表达**

**实测现象**

- 多篇候选仅靠标题和一句元数据展示，用户很难判断哪篇是原文真正引用的论文。
- 没有把“最可能的原文引用项”置顶或用不同颜色突出。
- 没有展示置信度，也没有解释为什么它更可能。

**期望**

1. 候选默认按“原文引用可能性”排序，最可能项固定在第一位。
2. 最可能项使用与普通候选不同的颜色/边框/标签，但必须同时有文字说明，不能只靠颜色。
3. 每项显示置信度档位或校准分数，并给出依据，例如：
   - 标题/副标题相似；
   - 作者重叠；
   - 年份接近；
   - 刊物/会议匹配；
   - DOI/arXiv/PMID 命中；
   - 摘要或关键词与引用上下文重叠；
   - 已在论文参考文献表中出现。
4. 置信度不是装饰性百分数；若未校准，应明确标为“匹配分”或“高/中/低”，不能伪装成概率。

**验收**

- 用已知参考文献集测试，首位命中率、Top-3 命中率有可复现统计。
- 最可能项有显著视觉标记 + 文字原因 + 置信度。
- 多项高度相似时允许标记多个候选项，不强迫系统伪造唯一正确项。

### R-009 候选论文检索路径单一

**严重度：P1｜类型：召回率 / 检索架构**

**当前实现事实**

- 标题/作者/刊物/年份最终被拼成一个文本查询。
- 当前非 DOI/arXiv 路径只调用一次 OpenAlex `search`，默认取 5 条，然后直接展示。
- 没有 Crossref 题录搜索、arXiv 标题检索、引用上下文特征、作者/年份/刊物的独立加权或多路结果融合。

**判断**

用户的怀疑有事实依据：当前检索路径确实偏单一，尤其遇到标题改写、副标题省略、中文引用转英文题名、作者姓名格式差异或会议/期刊改名时，召回率可能不足。

**改进方向（待设计验证，不是本轮实现）**

- 多路候选生成：DOI/arXiv 精确路径、OpenAlex 题录搜索、Crossref bibliographic query、arXiv 标题搜索。
- 查询变体：完整标题、去掉副标题、标题+第一作者、标题+年份、作者+刊物+关键词。
- 去重与融合：DOI > arXiv > 规范化标题，再按作者/年份/venue/摘要相似度重排。
- 利用“引用上下文”：把引用句、所在段落和被引编号作为轻量重排信号。
- 记录每路来源与命中原因，便于解释和调试。

**验收**

- 建立至少 30 条真实引用查询的离线基准集，覆盖期刊、会议、预印本、改名论文和作者姓名差异。
- 指标至少包含 Recall@5、Top-1 accuracy、Top-3 accuracy、重复候选率和无结果率。
- 多路检索不得增加无意义请求风暴；每路设置超时、降级和缓存。

### R-010 阅读主框宽度与 4:6 全屏布局

**严重度：P1｜类型：布局 / 响应式**

**实测现象**

- 阅读主框宽度上限不足。
- 在传统显示器比例、DSH 全屏、主对话与插件画面约 4:6 时，插件内部仍留下大量左右空白。

**当前实现事实**

- `.dpr-readerLayout` 当前 `max-width: 980px`。
- 内部为固定 `132px` 目录 + `16px` 间距 + 主文章列。
- 宽度增长到一定值后被 `max-width` 截断，而不是继续响应插件 pane 的实际宽度。

**期望**

- 不把思路局限成“把 980px 调大”，而要根据 pane 实际宽度设置连续占比/分段曲线。
- 目标场景：1920×1080、2560×1440 全屏，DSH 主对话:插件约为 4:6。
- 插件内容应占据主工作区绝大部分宽度；常规阅读行宽仍受控，不能变成跨屏超长行。
- 可考虑“目录列按 pane 比例扩展 + 正文列自适应 + 阅读行宽单独限幅”，避免只放大外框仍把正文挤在中间。
- 窄屏和大屏都要有明确断点，不允许横向滚动或目录遮正文。

**验收**

- 在 1920、2560、3440 宽度以及 4:6 分栏下测量 pane、目录、正文卡、左右空白。
- 定义可量化标准，例如常规全屏下正文卡左右总空白不超过 pane 的 15%–20%，同时正文 measure 不超过可读上限。
- 375px、768px、桌面半栏与全屏均通过截图和盒模型断言。
- 加宽后引用、批注、公式、表格和中文/对照模式不退化。

**必须坚持的产品判断**

PDF → 阅读页不是装饰功能，而是整个插件的内容底座。结构顺序、块类型、锚点或中文对照错误，会进一步污染引用、批注、翻译、检索、问答和版本对照。不能继续用“几个样例能打开”作为完成标准。

1. **建立分型语料库**

   - 全宽图/表；
   - 算法框、代码块、带编号步骤；
   - 跨页段落、跨页表格；
   - 行内/编号/多行公式；
   - 脚注、边注、页眉页脚；
   - 参考文献、附录、Supporting Information；
   - 预印本 HTML 与正式版 PDF。

2. **原页与转义页双视图核对**
   - 每个 block 同时记录 `page / bbox / sourceIds / type / order / translatedUnitId`；
   - 左边看原 PDF 页面，右边看中文/对照阅读页；
   - 逐段标记正确、遗漏、重复、错序、错型、错译和锚点错位。

3. **建立结构与翻译金标**
   - 不要求人工重写全文，但至少为每类结构准备关键段真值；
   - 算法/表格/公式必须有完整真值；
   - 所有真值带原页页码与 bbox。

4. **量化指标**
   - 文本块覆盖率；
   - reading-order accuracy；
   - block-type accuracy；
   - 表格/算法结构完整率；
   - 中文翻译块与原文块锚点对齐率；
   - 目录/结构块污染率；
   - 重复块率、漏块率、跨栏错序率。

5. **根因闭环**
   - 每个失败必须归入：字符识别、栏检测、阅读顺序、块分类、结构重建、翻译分块、锚点或渲染；
   - 先写最小复现 fixture，再改算法；
   - 算法升级后同时跑旧语料与新语料，防止只修好当前 PDF。

6. **迭代门禁**
   - 新增 PDF 失败 → 加入语料库；
   - 修复前有失败断言；
   - 修复后结构指标提升且无旧样本回退；
   - 中文模式逐段对照通过，不能只验证原文 HTML。

**验收**

- 至少完成一轮跨论文、跨版面结构审计报告。
- Algorithm 1 这类编号步骤块有独立类型、层级和翻译单位。
- 目录中不出现 `BEGIN/END`、表格行或正文碎片。
- 原文、中文、对照三态在相同 blockId 下保持结构一致。
- 每个已知失败都有 fixture 和回归项。

### R-014 目录滚动时顶部被遮挡

**实测现象**

- 正文向下滚动时，左侧目录最上方第一条以上的区域会被论文标题板块或阅读工具栏遮挡。

### R-015 切换页签后阅读位置回到顶部

**严重度：P1｜类型：状态保持 / 阅读连续性**

**复现**

1. 打开论文阅读页并滚动到中段。
2. 切到主界面或其它插件页。
3. 再次打开同一论文阅读器。
4. 页面回到最上方，而不是上次离开的位置。

**当前实现线索**

- 恢复应发生在正文完成渲染且目标块尺寸稳定之后，不能先跳到 0 再延后。

- 不出现闪烁式先回顶部再跳回。

### R-016 批注问答策略：先回答问题，克制批判，默认讲解/联网补充

**严重度：P1｜类型：模型提示词 / 回答产品性**

**实测现象**

- 模型倾向于对选段持续挑毛病、找局限或提出修订，偏离“帮助用户理解论文、寻找灵感”的主要目标。
- 有时没有先回答用户批注里的明确问题。

**产品定位**

论文精读辅助不是审稿系统。批判性可以保留，但不能成为默认主任务。

**默认回答契约**

1. **先答用户问题**：用户问什么就回答什么，第一段直接给结论或解释。
2. **主任务是解释与分析**：厘清概念、论证链、因果、实验设计和上下文。
3. **总结后再补充局限**：批判性内容只放在末尾“局限/需注意”简短段落，通常 1–3 点，不抢主回答。
4. **没有明确问题时**：默认做讲解、结构化总结、关键术语解释、与全文其它章节的关系梳理。
5. **外部信息补充**：若用户没有强制限定“只根据原文”，且当前会话具备网页检索能力，可主动检索必要背景；回答必须区分“论文原文 / 外部资料 / 模型分析”，并附来源。
6. **无联网能力时**：明确标记“未做外部核验”，不能假装查过。
7. **不得擅自扩题**：批注只涉及一个概念时，不自动展开整篇论文批判。

**验收**

- 固定测试问题集：事实解释、术语、方法理解、图表读数、灵感延展、明确要求批判。
- 每题的“是否先回答用户问题”评分必须通过。
- 用户未要求时，批判部分不超过回答末尾一小节。
- 联网路径与纯原文路径在回答中标清证据边界。

### R-017 回答需要理解后重组，而不是复读原文

**严重度：P1｜类型：总结 / 推理表达**

**实测现象**

- 回答常把原文换一种说法复述，缺少“读完之后的重新组织”。
- 对复杂内容没有形成问题—证据—推理—结论或概念—关系—含义的结构。

**期望**

- 对选段进行压缩、归类和关系重建：
  - 这段在回答什么问题；
  - 作者用了什么证据/机制；
  - 得出什么结论；
  - 与全文其它部分如何连接；
  - 对用户寻找灵感有什么可迁移点。
- 保留必要的原文短引，但原文引述不能占据回答主体。
- 对复杂句先拆概念，再合并成用户能复述的短结论。
- “批判”不是默认输出；“解释到位”才是默认成功标准。

**验收**

- 建立复读检测：回答中连续复述原文的长度不得超过必要引证范围。
- 每个长回答至少有一个结构化总结（列表、表格或清晰段落）。
- 用户读完后能得到比原文更短、更清楚的知识结构，而不是同义改写。

### R-018 长表格部分转成 Table，剩余行退化成文字

**2026-10-21 审计实验记录**

- Table 1/3/4 的旧 bbox 分别在 334.818 / 341.733 / 675.794 处被截断。
- 修复后以连续规则链和同列表格行扩展表体；AIoT 5 个表的 `tableText` 换行数依次为 40/8/81/7/12。
- 审计新增 `table.crop-cuts-data-rows` 与 `table.text-flattened`；本次 after 均为 0。
- 单元格行列语义、跨页表合并仍待单独金标。

**严重度：P1｜类型：表格检测 / 结构重建**

**实测现象**

- 转义时长表格只提取了部分内容以 Table 形式呈现。
- 其余行变成普通段落逐行堆叠，丧失列关系、行关系和数值对齐。
- 这是严重的数据结构损失，不只是视觉问题。

**待补证据**

- 下一次测试记录 PDF、页码、Table 标签、原表截图、MirrorDoc 中对应 block 列表。
- 统计“原表行数 / 识别为 table 的行数 / 退化为 paragraph 的行数”。

**可能根因（待验证）**

- 表格边界框只包住前半段；
- 跨页表被拆成多个独立块且后续块分类失败；
- 表格线/留白规则不适用于无框表或稀疏长表；
- `table` block 内部分行在 reconcile 阶段被重新按段落切割；
- 视觉补全只针对已标记为 `table` 的 block，未标记部分不会进入表格链路。

**期望**

- 长表和跨页表必须维持一个逻辑表或多个显式 continuation block，不能把剩余行偷偷降级成正文。
- 无法可靠恢复列结构时，保留整张原表图像并明确告警，不能只展示半张结构表。
- 行号、列头、单位、脚注、续表标记必须保留。

**验收**

- 每个测试表输出完整性报告：原表行数、解析行数、缺失行、退化行、跨页段数。
- 长表不出现部分 table + 部分 paragraph 的混合静默失败。
- 中文表格译文只在结构完整且数字校验通过后展示；否则保留原表。

### R-019 研究模式 / 灵感模式

**严重度：P1｜类型：批注问答定制 / 研究流程**

**产品定位**

研究生、博士生阅读论文通常服务于自己的研究方向，或者正在通过论文寻找开题方向。现有默认问答应继续以“准确理解论文”为主；两个可选模式只定制回答末端的分析视角，不改变 PDF 转义、引用真实性或证据锚点规则。

| 模式 | 典型用户阶段 | 核心回答方向 |
|---|---|---|
| 未选择（默认） | 日常精读 | 解释概念、论证、方法、图表和上下文，帮助准确理解 |
| 研究模式 | 已有研究方向 | 分析选段对用户方向可提供的方法、实验、数据、对照、工具或方案灵感 |
| 灵感模式 | 尚未定方向/寻找开题 | 提取创新点，做技术迁移与发散，并查新已有工作 |

**入口要求**

- 在阅读页左侧目录下方提供“研究模式”和“灵感模式”两个按钮。
- 默认均未启用；当前启用的模式必须持续可见，不能静默生效。
- 建议两种模式单选互斥；是否允许同时开启作为后续产品决策，不能在本条中直接假定。
- 目录较长时，模式按钮应保持可发现，并避免与 sticky 目录遮挡问题 R-014 冲突。
- 窄屏目录为横向布局时，必须有对应的模式入口，不能只在桌面显示。

#### R-019-A 研究模式

**用户输入**

- 用户可以向大肥鱼说明当前研究方向、关心的方法、目标应用或正在做的课题。
- 研究方向应支持编辑和清空；默认只在本地保存，不进入公开仓库或其它用户数据。
- 待设计：研究方向按用户全局保存，还是按论文/项目保存；实现前必须明确，避免同一方向被错误复用。

**回答契约**

1. 前段仍先回答用户对选段的直接问题，不能因为开启研究模式就跑题。
2. 主体继续解释论文本身，保证事实和理解层准确。
3. 回答末尾增加“与你的研究方向”部分，分析选段可能提供：
   - 可迁移的方法或实验设计；
   - 可复用的数据、指标、工具或评价方式；
   - 可作为对照/基线/组合方案的部分；
   - 可进一步验证的假设或改进点。
4. 区分“论文明确支持”“模型推导”“与用户方向相关但尚未验证”三种层级。
5. 若选段与研究方向的关联很弱，应直接说明，不强行制造联系。

**验收**

- 同一选段在默认/研究模式下分别回答，研究模式只增加末端研究关联，不改变事实结论。
- 用户问题明确时，研究关联不得挤掉或延后直接回答。
- 研究方向为空时，不得只显示空泛模板，应提示补充方向或退回默认模式。

#### R-019-B 灵感模式

**回答契约**

1. 先解释选段，再提取 1–3 个可验证的创新点或技术机会。
2. 发散时说明创意的输入、变化、组合方式和潜在应用，不输出无边界脑洞。
3. 每个创意点至少包含：
   - 论文中的事实来源；
   - 可迁移/组合的技术；
   - 新方案设想；
   - 可能需要的数据、实验或资源；
   - 已知风险与反例。
4. 强化全网论文查新：对创意点提取检索关键词，查已有工作、相似方法和覆盖缺口。
5. 查新结果必须附论文题名、DOI/链接和相似点/差异点；没有真实检索时明确标记“未查新”，不得口头声称“未见研究”。
6. 对“创意是否已存在”的结论使用谨慎等级：
   - 找到高度相似工作；
   - 找到部分相关但存在差异；
   - 当前检索未发现，但不能证明绝对新颖。

**验收**

- 固定一组论文段落测试创新点提取，避免把作者明说的 contribution 和模型新增创意混在一起。
- 每个创意点都有原文锚点；每个外部查新结论有可点击来源。
- 在没有联网工具或检索失败时，回答仍能提供分析，但不得伪造查新。
- 外部检索不能阻断首段解释；超时或失败时降级为“创意分析 + 未完成查新”。

**模式边界**

- 两个模式只定制回答与可选检索，**不得改变** PDF 块顺序、引用锚点、批注保存、翻译证据和版本信息。
- 默认未选择时的产品目标仍是“准确理解论文”，不是审稿、修订或强行找创新。
- R-016 / R-017 的回答契约对两种模式继续有效：先答用户问题、克制批判、理解后重组。
- 研究方向属于用户个人研究信息，只允许在需要时进入模型上下文；不得写入公开日志、插件仓库或跨用户共享。

### R-020 “多篇综述”目标定义与自我调试方案

**严重度：P1｜类型：产品定义 / 多论文工作流 / 质量工程**

**背景**

当前已有“多篇综述”入口和双篇工作台能力，但用户仍不清楚这个功能究竟解决什么真实任务，说明入口文案、默认流程和调试目标没有把产品价值讲清楚。不能仅以“能同时打开两篇论文”作为完成标准。

**先定义它为什么存在**

候选目标（后续通过真实任务验证并收敛）：

1. **建立研究地图**：快速回答几篇论文分别在解决什么问题、方法路线是否相同。
2. **比较方法与结果**：把不同论文的对象、数据、指标、方法、结果放在同一张可追溯证据表里。
3. **寻找研究缺口**：识别已有工作未覆盖的条件、数据、场景或评价维度。
4. **形成综述初稿**：从有锚点的对照结果生成可继续编辑的结构化笔记/报告。
5. **复用灵感**：从多篇方法中组合出新的研究假设或实验设计。

不作为默认目标：

- 只是把两篇论文并排显示；
- 只是让模型对多篇论文写一段泛泛摘要；
- 默认逐篇挑错或写审稿意见；
- 在没有证据锚点时生成综述结论。

**建议的核心用户旅程**

### 旅程 A：2 篇方法对照

1. 从论文库选 2 篇同方向论文。
2. 系统先给出“为什么适合对照”的简短判断：任务、数据、方法或指标是否可比。
3. 生成七字段证据表。
4. 每格可跳回 blockId/page。
5. 用户基于某一格继续提问：“这两篇方法差异对实验设计意味着什么？”

### 旅程 B：3 篇研究缺口

1. 选 3 篇论文。
2. 系统先按研究问题/场景聚类，而不是机械横向铺表。
3. 突出共同覆盖、明显空白和互相矛盾。
4. 每个“缺口”必须附至少两篇论文的证据或明确标为模型归纳。

### 旅程 C：综述笔记/报告

1. 从已生成并检查过的证据表和用户批注出发。
2. 生成“背景—路线—对比—争议—缺口—下一步”的 Markdown。
3. 不允许引入表格之外且无锚点的事实。
4. 可导出本地归档。

**自我调试方案**

1. **建立真实任务集**
   - 同题不同方法；
   - 同方法不同数据集；
   - 综述论文 + 原创研究；
   - 结论相互冲突；
   - 版本不同但非多篇综述；
   - 明确不可比的论文作为负例。

2. **先做能力基线**
   - 当前摘要是否足以支持七字段；
   - 2 篇/3 篇时上下文是否截断；
   - 证据表锚点定位率和缺失率；
   - 工作台是否能围绕表格继续追问；
   - 生成报告中的无出处陈述数量；
   - 完成一个真实综述任务所需点击/等待/纠错次数。

3. **人工逐项评分**
   - 任务适配度：系统是否先判断论文是否可比；
   - 归纳质量：是否形成跨论文关系，而不是逐篇摘要拼接；
   - 证据真实性：每个事实是否可回 blockId；
   - 缺口质量：研究空白是否具体、可验证；
   - 可操作性：是否输出下一步实验/检索方向；
   - 回答聚焦：是否围绕用户问题，不自动跑成审稿报告。

4. **找错后分类**
   - 入口/文案没有说清目标；
   - 选文条件不适合对照；
   - 档案压缩丢信息；
   - 七字段定义不适合当前问题；
   - 证据锚点丢失；
   - 模型空泛归纳或强行比较；
   - 工作台交互无法承接下一步任务。

5. **迭代完善**
   - 每轮只改一类核心问题；
   - 改完用同一任务集复测；
   - 用“用户是否能据此推进真实研究任务”作为最终验收，而不是只看模型文本流畅度。

**首轮验收**

- 主界面入口用一句话说明多篇综述能做什么，用户无需猜测。
- 至少 3 条核心旅程在真实论文上跑通。
- 证据表锚点覆盖率、缺失项、模型归纳项可区分。
- 对不可比论文能直接提示“不适合按当前七字段对照”，而不是硬生成。
- 报告不得出现无锚点的事实性结论。

### R-021 独立“文档管理”页面与批量 PDF 导入

**严重度：P1｜类型：文档库 / 导入流程 / 信息架构**

**产品目标**

主界面增加“文档管理”入口，以独立页面集中管理本地论文，而不是只能从“最近论文”列表中操作少量文档。交互逻辑参考“云记”类应用的文档管理中心，但具体借鉴范围需在实现前做一次功能对照，不直接复制品牌或界面资产。

**入口与页面**

- 主界面提供明确的“文档管理”按钮/入口。
- 点击后打开单独页面，不挤在现有小体积 Hero 或最近论文区域内。
- 页面至少支持：
  - 列表/卡片视图；
  - 标题、作者、DOI/arXiv、导入时间、转换状态、批注数；
  - 搜索、排序、状态筛选；
  - 单篇打开、单篇删除/重试、批量选择和批量操作；
  - 重复论文/多副本/版本关系的显式展示。

**批量导入与按需转义**

1. 用户可一次选择或拖入多个 PDF。
2. 批量导入第一阶段只做轻量入库：
   - 保存 PDF；
   - 计算 SHA-256；
   - 读取基础元数据/文件名；
   - 标记状态 `imported`（已导入，未转义）。
3. 不要求批量导入时立刻跑完全部 PDF 转义。
4. 用户点击某个 PDF：
   - 若已有可用 MirrorDoc，直接进入阅读页；
   - 若尚未转义，进入后台转换并显示进度，完成后自动打开或给出明确“打开阅读页”按钮；
   - 转换失败时停留在文档管理页并显示可重试错误。
5. 可提供“批量后台转义”作为显式选项，但不能成为导入的强制前置。

**状态模型**

| 状态 | 含义 |
|---|---|
| imported | 文件已入库，尚未解析 |
| queued | 已排队等待转义 |
| converting | 正在提取/复核/渲染 |
| ready | 可打开阅读页 |
| failed | 转义失败，可重试 |
| missing | 原文件或关键产物丢失 |

**重复与版本**

- 同一 SHA 的 PDF 默认不重复导入。
- 同一 DOI/标题的多个副本需显式展示为“多个文件/多个版本”，不能静默覆盖。
- 删除、重转义、去重必须有明确作用域，避免误删批注或其它版本数据。

**批量操作边界**

- 批处理中单个文件失败不能中断整批。
- 每项都有独立错误和重试。
- 删除属于高风险操作，至少要有确认和影响范围说明；批注、归档与用户数据的处理规则必须先定。

**验收**

- 一次导入 10 个 PDF，页面不冻结；可立即看到每项状态。
- 点击未转义 PDF 能排队并在完成后打开。
- 点击 ready PDF 直接进入阅读页。
- 刷新/重启后文档状态和已导入文件仍存在。
- 批量删除、批量重试、重复文件、损坏 PDF、转换失败均有明确路径。
- 已有单篇批注、版本对照、论文库和多篇综述入口不退化。
